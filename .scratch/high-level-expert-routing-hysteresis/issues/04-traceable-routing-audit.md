# 04: 交付可追溯的逐步路由审计

**What to build:** 审计人员能够从一次完整回放逐步解释“观察到哪个主导 Slot、谁实际拥有决策权、候选为何等待或接管、最后执行了什么动作”，并通过既有 Decision ID 和真实预测证据追溯。保持、确认、切换、失效、规则接管与实际交易分别可见。

**Blocked by:** 03 — 贯通风险抢占与空槽平滑退出。

**Status:** ready-for-agent

依据本功能实施规格、ADR-0062 及既有审计证据链约束。依赖 03 是为了覆盖包括风险与空槽在内的完整可观察路由事件。

2026-10-25 最新实施约束：逐步路由审计由原地升级后的路由产生；允许同步升级现有审计/诊断消费者，保留真实预测、交易与账户证据链。不要求兼容旧 schema；新产物按版本与运行身份隔离，不覆盖历史实验。

- [ ] 公开审计产物逐决策记录观察到的主导 Slot、前后当前专家、前后候选与确认次数、双轴分数、H/E、退出比率、Δ、K、事件原因和最终动作；区分当前专家、主导 Slot 与防御状态。
- [ ] 候选完成确认并清零时仍能查到刚完成的候选身份、更新前次数及本次达到 K 的事实，不能只留下清零后的空状态。
- [ ] 原因足以区分专家保持、候选确认等待、替换、当前专家失效、首次进入、规则恢复，以及风险或空槽阻断；同一步失效并直接接管可同时还原关键事实。
- [ ] 路由事件与既有执行及账户证据共用 Decision ID；保留确定性的实验、合约、步骤身份，不另造无法关联的标识体系。
- [ ] Prediction Record 只代表真实模型推断：普通专家保持期间每步产生真实新推断的证据，规则-only、预热及无模型推断的空槽保持不伪造预测记录。
- [ ] 实际发生专家推断后又被风险约束拦截的场景，能够区分真实推断来源与最终动作原因，不把推断动作冒充执行动作，也不错误隐藏已经发生的推断事实。
- [ ] 专家切换次数不等于交易次数；不因 Slot 切换额外计手续费。交易及费用继续来自实际模拟执行记录。
- [ ] 通过公开路由和完整产物导出入口，回放进入、保持、候选变化、失效接管、规则等待、空槽和风险抢占序列，验证公共审计关联、步骤覆盖及既有发布校验约束。
- [ ] 相同输入、模型、配置及初始状态重复回放，候选排序、路由事件和关联键一致；升级后的消费者校验新 schema 与完整性，不静默把旧结果解释为新策略证据。
