# 02 — 强制涨跌停成交双重防护

**What to build:** 让 Base Futures Trading Environment 依据当前 `is_limit_down` / `is_limit_up` 同时约束可用动作和直接成交，使跌停无法卖出、涨停无法买入的真实成交能力不会被调用方绕过。

**Blocked by:** 01 — 暴露当前持仓真实成本状态。

**Status:** ready-for-agent

- [ ] 跌停时所有卖出数量都不可用，包括减平多头以及开出或增加空头；合法买入动作仍受订单簿和保证金约束正常执行。
- [ ] 涨停时所有买入数量都不可用，包括减平空头以及开出或增加多头；合法卖出动作仍受订单簿和保证金约束正常执行。
- [ ] 涨跌停硬约束只依赖当前显式涨跌停状态，不依赖 Label 名称、CLI 语义、near-limit 或单纯的价格接近程度。
- [ ] 不可成交目标从环境可用动作集排除；即使绕过掩码直接交给 step，环境也保持实际仓位、不产生税费/滑点/已实现盈亏，且不抛异常中断轨迹。
- [ ] Reverse Position 中任一腿要求涨跌停禁止方向时，目标从可用动作排除，直接执行时不虚构部分成交。
- [ ] 普通非涨跌停时的订单簿深度、mark price、税费、滑点、杠杆、资金费、维持保证金、强平和反手语义保持不变。
- [ ] 高层环境测试覆盖可用动作和绕过掩码两层，并与现有涨跌停 reward shaping 及反手回归一起通过。
