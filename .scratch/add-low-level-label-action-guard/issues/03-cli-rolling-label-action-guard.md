# 03 — 提供 CLI Label 语义与滚动动作配额

**What to build:** 提供独立的带守卫 Stage II validation 入口，让模型先在环境原始可用动作上表达原始意图，再由环境外部守卫根据 CLI Label 语义与滚动配额生成最终动作。

**Blocked by:** 02 — 强制涨跌停成交双重防护。

**Status:** ready-for-agent

- [ ] 带守卫入口使用确认的新名称，但不自动迁移 shell、IDE、文档或其他调用方；无守卫低层测试入口保持不变。
- [ ] 单一 CLI 映射支持跌停、大跌、小跌、震荡、小涨、大涨和涨停七类语义，并严格校验当次发现的全部 Label；守卫不读取外部 Label JSON。
- [ ] Q 网络始终接收环境原始 `avaliable_action`；守卫在原始动作产生后才执行，不将 Label 配额合并进模型掩码。
- [ ] 默认 10 步滚动窗口下，小幅容量为 4、大幅容量为 2、涨跌停容量为 0；可调比例按向下取整，轨迹起始即拥有完整容量。
- [ ] 逆向开仓、加仓和减仓后仍逆向占用配额；保持逆向仓位和完全平仓仅进入时间步分母；震荡 Label 不定义逆向动作。
- [ ] 超额原始动作在当前空仓或与 Label 同向时降级为保持，并记录原始动作、最终动作、守卫原因、当前逆向数与容量。
- [ ] 换手率、动作变化次数和动作历史使用最终交给环境的动作；仓位指标使用环境实际执行后状态。
- [ ] 完整行为轨迹测试覆盖 CLI fail-fast、配额计数、窗口滑出恢复、保持降级、轨迹状态隔离以及最终动作与执行仓位分离。
