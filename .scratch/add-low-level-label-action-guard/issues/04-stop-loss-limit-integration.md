# 04 — 贯通成本止损、涨跌停与守卫审计

**What to build:** 将当前持仓真实开仓价、涨跌停成交约束和滚动 Label 守卫贯通成完整 validation 行为轨迹，使被拦截的逆向持仓可按对称价格阈值尝试平仓，同时不虚构涨跌停下不存在的流动性。

**Blocked by:** 03 — 提供 CLI Label 语义与滚动动作配额。

**Status:** ready-for-agent

- [ ] 只有原始动作先因滚动配额被拦截时才评估止损，未发生配额拦截时不主动平仓。
- [ ] 下跌 Label 的逆向多头使用相对开仓价的价格下跌，上涨 Label 的逆向空头使用相对开仓价的价格上涨；达到或超过默认 3% 时生成完全平仓动作。
- [ ] 被拦截的逆向持仓未达阈值时降级为保持；多空恰好达到 3% 的边界均按平仓处理。
- [ ] 跌停时多头止损平仓、涨停时空头止损平仓被环境拒绝；明细记录守卫平仓最终动作，实际仓位继续保持。
- [ ] 逐步审计同时包含原始动作、最终动作、`allowed` / `quota_hold` / `stop_loss_close` 原因、配额状态、开仓价、持仓均价和执行后仓位。
- [ ] 滚动历史仍以交给环境的最终动作 ID 为事实，即使深度、保证金或涨跌停导致实际仓位不同。
- [ ] 定向验证覆盖全部三个新能力及现有无守卫入口、Reverse Position、Trading Process Feature 和涨跌停 reward shaping 回归，并完成 Python 编译检查与 OpenSpec strict validation。
- [ ] 交付说明未运行需要本地数据与 checkpoint 的全量 fu 10min/30min validation 回测，且不宣称收益保证或实盘可用性。
