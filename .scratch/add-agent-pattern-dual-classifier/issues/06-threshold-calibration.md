# 06 — 阈值标定:真实数据 goal-driven 循环

**What to build:** 端到端行为:用户拿到 04/05 跑出的真实明细表和聚合视图后,发现未分类率过高、某类从不命中、或盈亏在各类间无区分度——需要调阈值再重跑。本 ticket 提供一个 goal-driven 的标定循环,把提议阈值调到真实数据上分布合理的锁定值。

循环步骤:
1. 用 04 的脚本在真实 Detail CSV(如 `trading_action_detail_epoch_58.csv`,n≈366k)上跑一遍当前阈值。
2. 看诊断指标:
   - 未分类率(目标 < 30%)。
   - 7 类 K 线形态命中分布(无某类从不命中、无某类 >60% 压倒其他)。
   - 6 类策略形态命中分布。
   - 每个判别特征(阶跃比、指数拟合 R²、Z-score 线性 R²、vol_trend 等)在真实窗口上的直方图。
3. 调阈值(基于分布直方图,不拍脑袋)→ 重跑 04 → 验证分布改善。
4. 锁定阈值 → 更新 01/02/03 的测试 fixture → 回归测试覆盖。
5. 把标定过程与最终阈值写入研究文档(沿用 `docs/research/` 约定),便于未来追溯。

诊断输出建议:一个标定脚本,读 04 的明细表 + 中间特征值(04 实现时应转储每个窗口的特征值供标定),输出分布直方图与未分类率。

验证:未分类率 < 30%、无某类从不命中、盈亏在各类间有区分度(如 KT1 突破型盈亏方差显著大于 KM2 箱体型)。

这是数据科学循环,不是纯代码交付。工作模式是"跑 → 看分布 → 调 → 再跑",和 01-05 的代码交付不同。
