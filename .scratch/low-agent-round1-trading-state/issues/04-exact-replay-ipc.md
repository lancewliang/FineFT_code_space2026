# 04: 在经验回传、保存与采样中保留精确交易身份

**What to build:** 将带完整状态的采集结果经完整或 compact IPC 送入 CPU/GPU replay、保存恢复并采样，确保模型看起来相同但精确执行状态不同的经验仍可区分，也能定位对应老师行。

**Blocked by:** 03: 让单进程 Low Agent 观察双向退出记忆与完整执行状态。

**Status:** ready-for-agent

用户已确认生成本工单。依据：第一轮状态契约第4.2、6节及 ADR-0065；只扩展经验身份，保留既有容量政策。

- [ ] 样本携带当前及 n-step 终点的 df 身份、绝对行号、精确状态键和可恢复快照引用；导出时保存状态对象及 df 映射，不能只有不可逆 hash。
- [ ] teacher_state_key 与 exact_state_digest 使用同一规范序列化和同一值；全部 retained teacher fields 原精度参与，禁用风控字段规范零。
- [ ] D 区分行情位置、模型实际输入、精确状态和请求目标动作；O 区分累计回报、n_actual、有效折扣、终止/截断及终点观测和精确状态。
- [ ] float32编码相同但精确损益、退出步或持续状态不同的样本不合并；同一物理内容来自不同worker/episode可合并；标签数值和优先级不增加经验身份。
- [ ] 同组最多4种不同O、重复合并、第5种随机轮换、满格FIFO及索引回收保持；独立seed可复现，不按收益择优。
- [ ] CPU/GPU replay 与完整/compact路径得到一致的身份和下一状态；18维张量、n-step短窗及终止掩码保持契约语义。
- [ ] 保存/恢复后可重建老师行定位；旧格式经验被明确识别，不静默补零升级为新语义；记录组数、重复率和两类替换计数。
