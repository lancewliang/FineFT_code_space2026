# 底层独立评估持仓止损

Status: ready-for-agent

## Problem Statement

底层 Agent 独立评估可能持续持有亏损仓位；评估者需要可配置的止损机制和与既有选模流程一致的评估路径。

## Solution

在三个底层独立评估入口启用统一的持仓浮亏止损，默认 3%，可显式关闭或调整。触发后执行受真实盘口和交易限制约束的退出，结果沿用现有路径供选择器使用。

## User Stories

1. 作为评估者，我希望默认启用 3% 止损，以控制当前持仓的浮亏风险。
2. 作为评估者，我希望设置其他止损比例，以比较不同风险规则。
3. 作为评估者，我希望将比例设为零以关闭止损，以获得无止损的对照结果。
4. 作为评估者，我希望拒绝负数及非有限阈值，以避免不可解释的配置。
5. 作为评估者，我希望多头和空头使用一致的当前名义金额口径。
6. 作为评估者，我希望同向加减仓属于同一当前持仓，直到平仓或反手。
7. 作为评估者，我希望每个观察步在策略动作前检查止损，以便动作保持不会跳过检查。
8. 作为评估者，我希望触发后优先退出并打断动作保持，以停止新增风险。
9. 作为评估者，我希望未成交或部分成交时持续退出，即使浮亏后来回落。
10. 作为评估者，我希望退出受盘口深度、涨跌停、手续费及滑点约束，以反映执行条件。
11. 作为评估者，我希望空仓后恢复策略决策，并允许同方向重新入场。
12. 作为评估者，我希望止损直到实际退出成交才结束，以区分平仓请求和实际成交。
13. 作为评估者，我希望每个数据片段与初始仓位独立维护止损状态，避免跨回放泄漏。
14. 作为评估者，我希望三个独立评估入口应用相同语义。
15. 作为研究者，我希望不同阈值的评估都沿用现有结果路径。
16. 作为研究者，我希望选模继续读取既有路径并能找到原始模型权重。
17. 作为研究者，我希望评估脚本支持环境变量设置止损阈值。
18. 作为研究者，我希望训练探索也应用止损，同时保留现有高层风控。
19. 作为评估者，我希望实际残余仓位保留真实数量，部分平仓不会使环境崩溃。
20. 作为评估者，我希望知道 3% 是离散观测的触发线，并非保证实际成交损失上限。

## Implementation Decisions

- 独立评估及多样化训练探索接入；预训练专家轨迹和训练所属评估保持原行为，高层现有持仓浮亏硬止损、冷静期和断路器不变。
- 亏损比例为当前浮亏除以绝对持仓数量与当前标记价的乘积，等于阈值时触发；空仓不触发。不得使用分母不同的当前持仓收益率替代。
- 每个回放实例维护独立退出状态。触发后持续请求目标空仓直至实际成交后的仓位为零；即使浮亏回落仍保持退出，不允许反手或新增风险；无额外冷静期或断路器。
- 实际仓位可能因部分成交偏离离散档位；独立评估和启用止损的训练探索支持这种残余仓位，真实数量用于盈亏及成交，固定维度动作编码仅在必要时映射到最近档位。
- 指定子 Agent、批量子 Agent 和集成平均策略均使用统一规则。评估结束仍有残余持仓时保留真实成交结果，不虚构平仓。
- 集成平均策略支持当前按标签类型、合约和标签组织的验证集，以及旧的标签目录布局；允许显式指定检查点目录。
- 默认阈值 0.03，0 表示关闭；CLI 和评估脚本可覆盖，有限非负数校验失败即报错。止损模块仅维护退出所需状态，不记录事件、计数或配置，不新增结果字段。
- 不依据止损阈值更改评估、日志或选择器的保存路径，也不单独保存止损配置；同一输出路径的后续评估会覆盖既有结果。
- 探索经验在退出待完成时将下一动作限制为平仓请求；环境仍依据实际盘口决定成交。训练被阻挡的平仓请求时，动作价值不施加动作选择掩码的巨大惩罚，监督分布和一般下一动作选择仍应用对应掩码。
- 保留工作区中既有修改和历史设计记录，不将回滚前的实现或测试结果视为当前代码事实。

## Testing Decisions

- 在独立评估入口以受控行情与真实环境验证外部行为；优先复用现有评估及环境测试接缝，避免依赖内部实现细节。
- 覆盖多空阈值边界、关闭规则、非法参数、动作保持抢占、涨跌停拒绝、部分成交、恢复后仍退出、退出后重新入场以及回放结束时未完成状态。
- 覆盖三个评估入口和训练所属评估、不同阈值沿用同一结果路径、选模读取与检查点路径、脚本参数传递。使用仓库现有合成盘口数据和真实环境测试作为先例。
- 在 finetf 环境运行对应回归，说明既有失败与未执行的真实数据评估。

## Out of Scope

预训练专家轨迹、奖励算法或模型结构变更；高层风控参数变更；新增止损冷静期、断路器或账户级回撤控制；实盘下单、发布及收益保证。
