# fineft-low-level-test-results Delta

## ADDED Requirements

### Requirement: Low-level test agent SHALL export directional behavior metrics for semantic selection

系统 SHALL 在低层 agent validation 测试聚合结果中输出方向行为指标和涨跌停行为指标，供后续 picker 判断候选 agent 是否符合 label 语义。

#### Scenario: Aggregate result includes directional behavior arrays

- **WHEN** `FineFT/RL/DiHFT/low_level/test_agent_index.py` finishes testing one `(label, initial_action, bin_index)` group
- **THEN** the aggregate result record SHALL still include `label`, `initial_action`, `bin_index`, `contract`, `df_path`, `reward_sum`, `df_length`, and `turnover`
- **AND** the record SHALL additionally include `mean_position`, `mean_abs_position`, `long_step_ratio`, `short_step_ratio`, `flat_step_ratio`, `long_reward_sum`, `short_reward_sum`, `flat_reward_sum`, and `net_position_exposure`
- **AND** the record SHALL additionally include `limit_up_step_ratio`, `limit_down_step_ratio`, `limit_up_long_reward_sum`, `limit_down_short_reward_sum`, `limit_up_reverse_short_ratio`, and `limit_down_reverse_long_ratio`
- **AND** every added field SHALL be an array with the same length as `contract` and `df_path`
- **AND** each array index SHALL describe the same validation slice as `contract[index]` and `df_path[index]`

#### Scenario: Direction metrics are computed from executed environment state

- **WHEN** the test loop records directional behavior for a validation slice
- **THEN** long, short, and flat step ratios SHALL be computed from executed `position_after`, not from requested action id alone
- **AND** `long_reward_sum` SHALL sum `step_reward` over steps where `position_after > 0`
- **AND** `short_reward_sum` SHALL sum `step_reward` over steps where `position_after < 0`
- **AND** `flat_reward_sum` SHALL sum `step_reward` over steps where `position_after == 0`
- **AND** `net_position_exposure` SHALL be normalized by `max_holding_number`

#### Scenario: Limit-state metrics use commodity price-limit semantics

- **WHEN** the test loop records涨跌停 behavior for a validation slice
- **THEN** `limit_up_step_ratio` SHALL be computed from existing commodity price-limit state, such as `limit_up_single_sided_ratio > 0` or current price touching `UpperLimitPrice`
- **AND** `limit_down_step_ratio` SHALL be computed from existing commodity price-limit state, such as `limit_down_single_sided_ratio > 0` or current price touching `LowerLimitPrice`
- **AND** `limit_up_long_reward_sum` SHALL sum `step_reward` over limit-up steps where executed `position_after > 0`
- **AND** `limit_down_short_reward_sum` SHALL sum `step_reward` over limit-down steps where executed `position_after < 0`
- **AND** `limit_up_reverse_short_ratio` SHALL measure the ratio of limit-up steps where executed `position_after < 0`
- **AND** `limit_down_reverse_long_ratio` SHALL measure the ratio of limit-down steps where executed `position_after > 0`
- **AND** the test loop SHALL NOT redefine quote legality; it SHALL reuse the price-limit columns and features generated by commodity preprocessing

#### Scenario: Aggregate CSV preserves JSON parseability for semantic metrics

- **WHEN** the system writes `analysis_result.csv`
- **THEN** the added directional behavior columns SHALL be serialized as JSON array strings
- **AND** those cells SHALL be parseable by `json.loads`
- **AND** the CSV SHALL preserve existing Chinese semantic headers for existing fields
- **AND** any new Chinese headers SHALL map one-to-one to the added machine fields

#### Scenario: Picker can reject stale aggregate results

- **GIVEN** an existing `analysis_result.npy` or `analysis_result.csv` was produced before directional behavior metrics existed
- **WHEN** semantic agent selection is enabled
- **THEN** picker SHALL reject the stale result
- **AND** the error message SHALL state that low-level testing must be rerun with semantic behavior and price-limit behavior metrics enabled

### Requirement: Directional behavior metrics SHALL remain validation-only selection evidence

系统 SHALL 只使用 validation 数据上的方向行为指标做 agent 选择，不得使用 test 数据调参或选择模型。

#### Scenario: Semantic metrics are generated from validation slices

- **WHEN** `test_agent_index.py` discovers files for semantic selection metrics
- **THEN** it SHALL read only validation slices under `valid/<contract>/label_*/df_*.feather`
- **AND** it SHALL NOT read final test split data for picker selection
- **AND** final test data SHALL remain reserved for post-selection evaluation
