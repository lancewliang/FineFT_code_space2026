## Context

本变更跨越两个现有边界：

1. Futures Trading Environment 负责基于订单簿的真实成交、滑点、税费、保证金、资金费、强平与实际仓位状态。
2. Stage II 低层 Agent validation 测试入口负责在 Market Dynamic Segment 上产生行为轨迹和可审计结果。

现有 Q 网络的 `avaliable_action` 是环境成交/保证金能力的硬掩码，不是 Label 风险偏好。如果把 Label 配额直接合并进该掩码，模型原始意图将不可观测，也无法在原始动作被拦截时触发按开仓价判断的降级逻辑。因此逐步 Label 动作守卫必须位于 Q 网络与环境之间。

环境已有交易结算结果对象，但只暴露整步滑点、税费和已实现盈亏；反手时平仓腿和开仓腿会合并，外部无法稳定重建新当前持仓的真实开仓价。成本状态必须由环境依据分腿成交元数据维护。

本变更面向 fu 等商品期货 10min/30min validation 切片的研究回测。它不使用 test split 调参，不改变 Stage I 训练或 Stage III 路由，也不构成实盘交易建议。

## Goals / Non-Goals

**Goals:**

- 使 Stage II validation 行为轨迹可以按 CLI Label 方向语义限制逆向仓位变化。
- 保留环境原始 `avaliable_action` 与模型原始动作，在环境外部产生最终动作。
- 让环境以真实成交口径维护当前持仓开仓价和持仓均价。
- 使环境在可用动作和直接执行两层都遵守涨跌停成交约束。
- 提供原始动作、最终动作、守卫决策和持仓成本的审计输出。
- 保持现有四维 Trading Process Feature、Reverse Position best-effort、订单簿深度、税费、滑点、资金费、维持保证金和强平契约。

**Non-Goals:**

- 不修改 Q 网络结构、模型权重、Stage I 训练或 replay buffer。
- 不将开仓价或持仓均价加入 `trading_info`。
- 不修改 Stage III Meta Router 的 Semantic Guard 软惩罚。
- 不修改无守卫低层测试入口、Agent 筛选逻辑或第二个类型/生命周期分析入口。
- 不对 `Simple_Env` 扩展本次成本状态与涨跌停双重防护。
- 不实现与动作拦截无关的主动止损系统。
- 不自动修改 shell、IDE、文档或其他调用方中的旧入口名称。
- 不将 near-limit 或 Label 名称当作环境层的硬涨跌停成交信号。

## Decisions

### 1. 逐步 Label 动作守卫放在模型与环境之间

模型仍使用环境原始 `avaliable_action` 计算原始动作。守卫之后依据 Label 语义、滚动配额、当前持仓和开仓价产生最终动作，再交给环境。

选择该边界的原因是它同时保留模型意图、环境成交契约和可审计降级。被拒绝的替代方案是直接合并 Label 掩码；该方案会使被拦截原始动作不可见，且使止损降级分支正常情况下无法触发。

### 2. Label 语义使用单一 CLI 映射

`--label_action_semantics` 使用逗号分隔的 `label:semantic_type` 形式，并严格覆盖当次 validation 发现的所有 Label。支持的类型为 `limit_down`、`strong_down`、`weak_down`、`sideways`、`weak_up`、`strong_up`、`limit_up`。

选择 CLI 而非 `label_semantics.json` 是为了让单次实验命令自包含语义，避免测试入口隐式读取与当次数据不一致的外部文件。该决策只限新的带守卫入口，不取消其他阶段已有的 Label manifest 契约。

### 3. 滚动配额使用最终动作历史

每条行为轨迹独立维护长度为 `window_size` 的历史。容量为 `floor(window_size × ratio)`，轨迹开始时即具有完整容量。守卫使用“最近 `window_size - 1` 个最终动作 + 当前候选”判断是否超额。

滚动分母中每个时间步都是一个动作。分子只统计产生逆 Label 仓位变化的最终动作：逆向开仓、逆向加仓和减仓后仍为逆向仓位。保持既有逆向仓位和完全平仓不进入分子；否则“被拦截后保持不动”会持续占用配额，窗口永远无法恢复。

### 4. 被拦截动作使用保持/条件平仓降级

被配额拦截时，当前为空仓或与 Label 同向则保持当前仓位。当前与 Label 反向时，按当前持仓开仓价计算对称不利变动：多头看价格下跌，空头看价格上涨。达到或超过默认 3% 时尝试完全平仓，否则保持。

止损不是独立的主动规则：只有当原始动作先被配额拦截时才评估。这避免把此变更扩大成新的通用止损系统。

### 5. 环境从分腿真实成交维护当前持仓成本

交易结算结果扩展可区分开仓腿的实际数量、成交额和开仓税费。环境据此维护：

- 多头有效开仓价 = `(开仓成交额 + 开仓税费) / 开仓数量`。
- 空头有效开仓价 = `(开仓成交额 - 开仓税费) / 开仓数量`。

成交额来自实际订单簿吃单，因此已包含滑点。只记录已发生的开仓税费，不预估未来平仓税费。

开启当前持仓的第一笔实际开仓成交设置开仓价；同向加仓只更新持仓均价，部分减仓不改变两个价格，完全平仓归零，反手使用新方向开仓腿重置。初始非零仓位未经过真实订单，使用首行 mark price 作为两个价格，不虚构税费或滑点。

成本价通过环境属性和独立 `info` 字段暴露，空仓为 `0.0`。它们不加入四维 `trading_info`，以遵守现有模型输入 ADR。

### 6. 涨跌停成交约束在环境内双重强制

环境只依据当前时间步 `is_limit_down` / `is_limit_up` 判断硬涨跌停状态：

- 跌停时禁止卖出，因而不能减平多头或开加空头。
- 涨停时禁止买入，因而不能减平空头或开加多头。

第一层在可用动作计算时排除不可成交目标。第二层在 `step` 内审核直接传入动作；即使调用方绕过掩码，环境也拒绝仓位变化并保持实际仓位，不抛出异常中断轨迹。

该规则的优先级高于守卫平仓意图和 Reverse Position 目标。例如跌停时逆向多仓达到止损，守卫可以生成平仓动作，但环境必须因无法卖出而继续持有。

### 7. 明细以最终动作为执行事实

步级明细保留模型原始动作，现有 `action` 字段表示最终动作，并增加守卫原因、当前逆 Label 数、容量、开仓价和持仓均价。换手率、动作变化次数和动作列表使用最终动作；仓位类指标继续使用环境实际执行后的仓位。

即使环境因深度、保证金或涨跌停未完成目标，滚动历史仍记录守卫交给 `step` 的最终动作 ID。这与用户指定的“交给 env 的动作”口径一致，同时保留目标动作与实际仓位差异作为成交诊断。

### 8. 使用两个高层测试接缝

环境能力通过 `Base_Env.reset/step` 验证，覆盖可用动作、直接执行防护、实际仓位、开仓价、均价和 `info`。守卫能力通过一条可控完整行为轨迹验证，覆盖 CLI、原始动作、滚动历史、最终动作、环境实际仓位和明细。

不以私有 helper 或内部 deque 作为主要测试边界，以允许实现在不改变外部行为的前提下重构。

## Risks / Trade-offs

- [交易结算结果增加分腿元数据可能影响旧调用方] → 新字段使用具名且有默认值的扩展，保留现有 tuple-compatible 契约，并运行旧反手/商品环境回归测试。
- [最终动作与实际仓位可能因涨跌停、深度或保证金不同] → 明细同时记录目标动作和执行后仓位，指标按已确定口径分别聚合。
- [滚动配额参数可在 validation 上过拟合] → 输出记录全部 CLI 配置和守卫证据；参数只能在 validation 上调整，test split 保留为最终评估。
- [按开仓价的 3% 不利变动不等同净 PnL 3%] → 字段和文档统一称为价格不利变动，不将其描述为账户收益率或保证金回报率。
- [初始非零仓位没有真实成交价] → 明确使用首行 mark price 的 Initial-action 情景特例，不虚构成交和税费。
- [涨跌停信号质量错误会直接限制成交] → 只消费现有商品预处理生成的 `is_limit_down/is_limit_up`，不在环境内重新解释原始行情。
- [明细 CSV 增加列并增大输出] → 只在已启用的逐步明细路径输出，不产生额外大型模型或数据副本。

## Migration Plan

1. 以向后兼容形式扩展交易结算结果，先使环境可维护成本价。
2. 在 `Base_Env` 增加成本价生命周期与涨跌停双重防护，保持 `Simple_Env` 不变。
3. 将原 type-index 守卫实验入口重命名为 `test_agent_index_with_guard.py`，在新入口增加 CLI、守卫、明细和最终动作指标。
4. 不迁移任何调用方；用户后续手动更新 shell 或 IDE 调用。
5. 运行定向环境/守卫测试、现有回归测试和 Python 编译检查。

回滚时可恢复原入口名称，删除守卫层，并停止消费新的环境成本字段；交易结算结果的向后兼容默认字段可保留，不要求大范围调用方回退。
