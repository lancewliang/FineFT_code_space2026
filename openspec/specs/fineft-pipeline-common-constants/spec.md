## Problem Statement

The FineFT project executes a multi-stage reinforcement learning pipeline for commodity futures (such as fuel oil `fu` at 30min frequency) consisting of:
- Step 2: FineFT Dataset Preparation (`commodity_contract_dataset.py`, `valid_cross_contract_label_calibration.py`, `vae_data_creation.py`)
- Step 3: Low-Level Agent Training (`weight_advantage_pretrain.py`)
- Step 4: Low-Level Agent Testing and Evaluation (`test_agent_index.py`)
- Step 5: Low-Level Agent Selection (`FineFT_single_agent_with_different_position.py`)
- Step 6: VAE Density Training and Evaluation (`VAE/main.py`)
- Step 7: High-Level Optuna Routing Optimization (`vae_routing_optuna.py`, `vae_routing_util.py`)
- Step 8: High-Level Heuristic Selection and Visualization (`DiHFT_high_level_heurstic.py`)

Across these interconnected stages, all file artifact names (e.g. `dataset_manifest.json`, `trained_model.pkl`, `analysis_result.csv`, `reward_history.npy`, `optuna_results.csv`, `high_level_agent_para.txt`) and DataFrame column identifiers (e.g. `tr`, `mdd`, `annual_sr`, `daily_cr`, `turnover`, `position`, `mark_price`) are currently hard-coded as ad-hoc, bare string literals in individual scripts.

From the developer and researcher's perspective, this architecture presents several critical friction points:
1. **Invisible Data Lineage**: Downstream analysis scripts (like `DiHFT_high_level_heurstic.py`) load numerous NumPy arrays and CSV files generated by upstream stages without explicit `import` statements. A reader cannot trace the origin of `wallet_balance_history.npy` or `optuna_results.csv` through static code analysis or IDE dependency graphs.
2. **Typo Propagation and Silent Regression**: When historical typographical errors occurred (such as `maintain_marigine_history.npy` with an erroneous `i`), the typo had to be copy-pasted across multiple disparate modules. Any divergence immediately triggers runtime `FileNotFoundError` or silent data corruption.
3. **Scattered Path and Filename Formatting**: Dynamic parameterized filenames (such as `df_{index}.feather`, `trading_action_detail_epoch_{epoch}.csv`, `label_{label}.npy`) are constructed using arbitrary, inconsistent inline f-strings across scripts without centralized contract validation.
4. **Refactoring Fragility**: Modifying or extending evaluation metrics or manifest schemas requires error-prone global text searches rather than compiler-enforced symbol renames.

## Solution

Establish a centralized, typed, modular constant package under `FineFT/common/` that cleanly partitions constants into three dedicated modules, unified under a top-level facade:

1. **`FineFT/common/artifacts.py`**:
   - `ArtifactNames`: Static file artifact identifiers with explicit extension suffixes (`DATASET_MANIFEST_JSON`, `TRAINED_MODEL_PKL`, `ANALYSIS_RESULT_CSV`, `ANALYSIS_RESULT_NPY`, `SELECTION_MANIFEST_JSON`, `TWO_DIMENSIONAL_SELECTION_MANIFEST_JSON`, `OPTUNA_RESULTS_CSV`, `CONTRACT_RESULTS_CSV`, `TRADING_INFO_NPY`, `RESULT_CSV`, `RESULT_ALL_CSV`, `BEST_RESULT_CSV`, `HIGH_LEVEL_AGENT_PARA_TXT`).
   - `HistoryArtifactNames`: Trajectory simulation vector filenames (`REWARD_HISTORY_NPY`, `TOTAL_ASSET_HISTORY_NPY`, `WALLET_BALANCE_HISTORY_NPY`, `UNREALIZED_PNL_HISTORY_NPY`, `INITIAL_MARGIN_HISTORY_NPY`, `MAINTAIN_MARGIN_HISTORY_NPY`, `NEW_POSITION_REQUIRED_MONEY_HISTORY_NPY`, `MICRO_ACTION_HISTORY_NPY`, `MACRO_ACTION_HISTORY_NPY`).
   - Parameterized filename builders: Pure functions with type hints (`get_df_chunk_filename`, `get_valid_processed_filename`, `get_trading_detail_csv_filename`, `get_vae_label_filename`, `get_vae_test_filename`, `get_heuristic_plot_filename`).
2. **`FineFT/common/metric_columns.py`**:
   - `MetricColumns`: Standardized DataFrame metric columns across evaluation, agent selection, and Optuna optimization (`TR`, `PORTFOLIO_TR`, `MDD`, `ANNUAL_SR`, `DAILY_CR`, `DAILY_VOL`, `DAILY_SOR`, `REQUIRED_MONEY`, `TRIAL_ID`, `REWARD_SUM`, `REWARD_MAX`, `NORMALIZED_REWARD`, `MEAN_TURNOVER`, etc.).
3. **`FineFT/common/trade_columns.py`**:
   - `TradeColumns`: Execution, action, and state observation columns (`POSITION`, `TURNOVER`, `INITIAL_ACTION`, `BIN_INDEX`, `PREVIOUS_ACTION`, `AVALIABLE_ACTION`, `REALIZED_PNL_STEP`, `UNREALIZED_PNL`, `WALLET_BALANCE`, `MARK_PRICE`, `IS_LIMIT_UP`, `IS_LIMIT_DOWN`, `LOWER_LIMIT_PRICE`, `UPPER_LIMIT_PRICE`, etc.).
   - Bilingual CSV mapping dictionaries: `CSV_HEADER_LABELS` and `AGGREGATE_JSON_COLUMNS` centralized from `test_agent_index.py`.
4. **`FineFT/common/__init__.py`**:
   - Exposes all primary classes and helper functions as a clean facade, supporting both `from common import ArtifactNames, MetricColumns` and granular sub-module imports.
5. **Full Pipeline Refactoring (Steps 2~8)**:
   - Systematically replace all string literal references across Steps 2 to 8 with explicit imports from `common`, strictly preserving underlying string values for 100% backward compatibility with serialized experiment directories.

## User Stories

1. As a quantitative researcher reading `DiHFT_high_level_heurstic.py`, I want to see explicit imports from `common.artifacts` and `common.metric_columns`, so that I immediately understand which upstream files and metric columns the heuristic picker depends on.
2. As a reinforcement learning engineer modifying `test_agent_index.py`, I want to import `HistoryArtifactNames.REWARD_HISTORY_NPY` and `ArtifactNames.ANALYSIS_RESULT_CSV`, so that I never misspell output filenames when exporting evaluation trajectories.
3. As a developer inspecting `vae_routing_util.py`, I want the historical typo in `maintain_marigine_history.npy` to be safely abstracted under `HistoryArtifactNames.MAINTAIN_MARGIN_HISTORY_NPY`, so that new code uses clean English while existing saved experimental folders remain fully readable.
4. As a machine learning engineer running Optuna hyperparameter searches in `vae_routing_optuna.py`, I want `optuna_results.csv` and `contract_results.csv` to be defined as `ArtifactNames` constants, so that any path resolution changes are centralized in one file.
5. As an agent evaluation developer in `FineFT_single_agent_with_different_position.py`, I want `REQUIRED_RESULT_FIELDS` to be built from `TradeColumns` and `MetricColumns`, so that the required schema fields are typed and immune to accidental column omission.
6. As a data pipeline engineer in `commodity_contract_dataset.py`, I want to use `get_df_chunk_filename(index)` rather than format strings, so that chunk feather naming conventions (`df_0.feather`, `df_1.feather`) are guaranteed consistent across training and validation.
7. As a data engineer in `valid_cross_contract_label_calibration.py`, I want `get_valid_processed_filename(contract)` to construct `valid_processed_{contract}.feather`, so that downstream VAE and test scripts resolve the exact same paths.
8. As a deep reinforcement learning developer in `weight_advantage_pretrain.py`, I want model checkpoint names (`trained_model.pkl`), feature arrays (`state_features.npy`), and margin dicts (`maintenance_margin_ratio_dict.npy`) to be imported from `ArtifactNames`, so that training checkpointing aligns with testing loaders.
9. As a VAE modeling researcher in `FineFT/RL/DiHFT/VAE/main.py`, I want `model_latest.pth`, `routing_summary.json`, and `id_logpx.npy` to be imported from `ArtifactNames`, so that Stage II outputs match Stage III inputs.
10. As an IDE user, I want autocomplete for all DataFrame column names via `MetricColumns` and `TradeColumns`, so that I avoid typos like `daily_vol` vs `daily_volatility` or `annual_sr` vs `sr`.
11. As a software architect, I want `FineFT/common/` to be divided into `artifacts.py`, `metric_columns.py`, and `trade_columns.py`, so that different categories of constants do not pollute a single monolithic file.
12. As a developer writing tests, I want `from common import ArtifactNames, MetricColumns, TradeColumns` to work directly out of `common/__init__.py`, so that test assertions can concisely reference official column and file constants.
13. As a systems engineer, I want `data_preprocess/` to remain untouched by this refactoring, so that the standalone feature extraction operators retain their decoupled runtime environment.
14. As a continuous integration system, I want unit tests in `FineFT/tests/test_common_constants.py` to verify that all constant strings match expected values, preventing accidental regression during future refactoring.
15. As a code reviewer, I want zero defensive bloat (`getattr`, `hasattr`, redundant fallback checks) introduced during this refactoring, adhering strictly to CLAUDE.md principles.

## Implementation Decisions

### 1. Package Structure Under `FineFT/common/`

The new package will consist of exactly four files:
- `FineFT/common/__init__.py`
- `FineFT/common/artifacts.py`
- `FineFT/common/metric_columns.py`
- `FineFT/common/trade_columns.py`

## Testing Decisions

1. **Unit Test Suite (`FineFT/tests/test_common_constants.py`)**:
   - **Literal Invariance**: Validate that each constant's string value exactly equals its canonical filesystem / DataFrame string.
   - **Historical Typo Guard**: Explicitly assert that `HistoryArtifactNames.MAINTAIN_MARGIN_HISTORY_NPY == "maintain_marigine_history.npy"`.
   - **Builder Correctness**: Verify return values of `get_df_chunk_filename(3)`, `get_valid_processed_filename("fu2401")`, `get_trading_detail_csv_filename(45)`, etc.
   - **Bilingual Mapping Completeness**: Validate that `CSV_HEADER_LABELS` contains all expected keys from `AGGREGATE_JSON_COLUMNS`.
2. **Smoke Test of Refactored Modules**:
   - Run `python -c "import FineFT.common as c; from common import ArtifactNames, MetricColumns, TradeColumns"` to verify imports across environments.
   - Verify that existing unit tests under `FineFT/tests/` pass with zero regressions.

## Out of Scope

1. **`data_preprocess/` Operators**: All feature engineering, downscaling, and merge scripts under `data_preprocess/` remain untouched.
2. **Algorithm and Model Semantics**: No changes to Q-network structures, VAE loss functions, Optuna trial logic, or trading environment execution logic.
3. **Renaming Existing On-Disk Files**: Existing experiment directories, log directories, or trained weight files on disk will not be renamed or migrated.

## Further Notes

- Implementation should follow a two-phase rollout:
  - **Phase 1**: Create `FineFT/common/` package and its comprehensive unit test suite (`FineFT/tests/test_common_constants.py`).
  - **Phase 2**: Refactor downstream analysis (Steps 7~8), followed by evaluation and selection (Steps 4~6), and finally data preparation and training (Steps 2~3).
