# Use Shared Cross-Contract Dynamic Label Thresholds

FineFT preserves the existing Butterworth, turning-point, slice-and-merge, and Dynamic_labeler algorithm, but fits one shared set of Semantic-free Dynamic Label thresholds from all contracts in the valid set and applies it to every contract. Production cross-contract calibration supports final `slope` labeling only; `quantile` remains an internal contract-local merge constraint, while final `quantile` and `DTW` requests fail fast. Segment scores retain the existing shared signed percentage-slope scale (`100 * segment_price_slope / segment_start_price`): this removes price-unit differences without taking the absolute value or dividing by each contract's volatility. Shared slope thresholds preserve the current `risk_bond=0.1` low/high selection, low-index `+2` offset, and `dynamic_number - 2` interval formula exactly rather than replacing them with standard quantiles. Each final market dynamic segment contributes one equally weighted score; segment length and contract identity do not change its calibration weight. Per-contract or per-label sample proportions are not balancing targets because forcing equal proportions would require contract-local final thresholds and would destroy the common cross-contract calibration needed by downstream merged training data. A contract may legitimately have no segments assigned to one or more labels; the Slice Manifest records every such label with zero files, zero rows, and an empty file list, while downstream array creation omits empty arrays. If all participating contracts together yield one to four final segments, calibration uses the existing min/max fallback and permits empty labels; only a zero-segment build fails. The same dataset-level rule applies whether the valid set contains one contract or many; a single contract is not a separate compatibility branch. Cross-contract calibration is a valid-dataset build: any change to the valid contract set triggers re-segmentation and threshold refitting for all contracts, followed by atomic replacement of all label outputs rather than incremental per-contract publication. The production entry point accepts the complete valid directory; single-contract mode is diagnostic only and cannot publish the official Slice Manifest or label directories. Contracts with insufficient rows for filtering are recorded as skipped and excluded from calibration, but missing columns, non-finite values, or segmentation failures abort the whole build and leave the previously published generation unchanged. The Slice Manifest records the participating contracts, final segment count, shared thresholds, dynamic count, labeling method, and percentage-slope statistics for audit and reproduction. Slice Feather State Features remain exactly as produced by the upstream train-only Scale Save; this decision adds no second feature-scaling stage and does not modify the scaler. Downstream VAE, selection, and model artifacts do not carry or enforce a calibration identifier; rebuilding them after recalibration remains an orchestration responsibility rather than a fail-fast compatibility check.
