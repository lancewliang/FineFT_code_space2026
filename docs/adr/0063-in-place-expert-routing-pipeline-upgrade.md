# 0063. 步骤 7–10 原地统一升级，不保留旧路由兼容路径

后处理代码固定依赖旧路由目录、参数序列化和最终评估入口，仅新增三个 expert 文件不能形成完整流水线。用户明确要求“全面升级不再向后兼容，所有后续步骤都需要升级”，随后确认“解除冻结，原文件直接升级”。因此原地统一升级高层 Optuna、筛选与可视化、主副合约同步评估、最终测试四个步骤；保留 ADR-0062 的 Q1–Q11 迟滞语义和风险边界，取代其此前的实施隔离方案。

## 取代的实施约束

解除 vae_routing_util.py、vae_routing_optuna.py、vae_optuna_fu_10.sh 及其他现有生产源码的冻结；不再强制另建 expert 三文件或禁止导入两个原 VAE 路由模块。共享工厂、公共参数定义、筛选器、最终评估、诊断/审计与必要测试均可同步修改。升级后的流水线使用 expert_hysteresis 及新版配置/产物契约，不维护 absolute/hierarchical、旧目录名参数推断或旧不完整文本参数的兼容分支。

## 决定

- 原步骤 7 `vae_optuna_fu_10.sh`、8 `high_level_heurstic_fu_10.sh`、9 `final_result_fu_10_main_sub.sh`、10 `final_result_fu_10.sh` 全部纳入验收，同一执行链与配置契约贯穿寻优、可视化及最终评估。文件名含 vae 不代表保留旧行为，因为评分仍使用 VAE。
- 统一版本化的完整已解析实验配置及其哈希，记录策略、H/E、退出比率、Δ/K、每个 Trial 的两轴窗口/gamma 与预热规则、模型/数据边界、资金/费用/风险以及 study/Trial/目标身份。CSV 和可读参数文本仅作投影；缺字段、旧 schema、身份不匹配明确失败，不补默认值继续评估。
- 2026-10-25 用户追加：策略使用的两轴窗口、两轴 gamma 继续与迟滞参数一起搜索，取代原“校准期间固定评分参数”的设计。模型/Manifest/参考分布固定，九维搜索选定最佳 Trial 后才冻结其完整评分与路由配置。搜索维度增加会增加校准成本，报告应将其标为联合优化结果，不把评分协议变化的效果全部归于迟滞。
- 用户确认步骤 8 沿用步骤 7 按预先固定目标选出的最佳 Trial，只校验、导出并可视化。其他绩效仅作诊断，不再次选参；lean trials 与一次最佳完整回放继续适用。需区分含惩罚目标与原始绩效，不依赖扫描已落盘轨迹挑候选。
- 步骤 9 默认用于指定校准/验证段的主副合约时间同步诊断；显式 test 同样只消费冻结配置。步骤 10 执行最终 test；各阶段、用途结果隔离，最终结果不反馈选参。后续 shell 默认值不能覆盖已选资金、费用或风险协议。
- 收益与 B&H、真实执行摩擦、风险及路由迟滞状态需要共同可视化，并按合约、时间/步骤和 Decision ID 对齐。取消旧格式兼容不取消风控、真实账本与审计证据要求。
- 取消代码兼容不授权删除历史产物。新版 schema、实验、阶段和用途使用独立存储范围；冻结模型及来源身份匹配的原始逐点分位缓存继续只读共享，窗口/gamma 平滑及预热状态在各 Trial 内独立处理。派生平滑缓存须按四项评分参数及算法/边界身份区分；缺失或不匹配时在新范围生成或明确失败。

## 权衡与验证

统一原有执行链可消除两套实现长期漂移和下游参数丢失，代价是旧参数包、脚本参数和结果读取方式需要重新准备；历史对照使用存档或独立历史代码版本。不能用兼容旧格式的隐式回退掩盖迁移缺项。

验收覆盖全部四个入口、选定 Trial 与配置无损传递、目标/绩效区分、资金风险一致性、valid/test 与 main_sub/final 隔离、旧 schema 拒绝、迟滞图表和审计对齐；实际独立研究评估在实现集成后执行。本轮仅确认设计并更新文档，不代表代码已升级或已经运行校准。
