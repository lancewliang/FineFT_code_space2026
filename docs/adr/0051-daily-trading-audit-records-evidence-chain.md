# 0051. 每日交易审计记录与可溯源证据链架构

为解决历史回测无法在每个 TradingDay 上稳定追溯“模型当时输出了什么、策略实际执行了什么、执行后账户发生了什么”的问题，消除仓位归零时重置账户历史导致的信息丢失，我们决定确立**每日交易审计记录与可溯源证据链架构**：采用追加写入（append-only）的三类核心记录（`prediction_records.csv`、`trade_records.csv`、`account_records.csv`），基于显式 TradingDay 严格分区，通过确定性 ID 相互关联，并引入暂存区校验与原子发布机制。

## Status

accepted

## Context

在先前的回测体系中存在以下结构性审计缺陷：
1. **账户历史在平仓时重置**：`base_env.py` 在持仓变为 0 时清空并重置 `wallet_balance_history`、`unrealized_pnl_history` 等，导致回测结束后留存的账户历史仅为最后一段持仓，无法还原全周期账户净值变化；
2. **模型推断输出未完整留存**：策略网络各动作的 Action Value（Q 值）、最优对比次优的 margin、高层路由门控证据以及动作可用性掩码未作为不可变事实固化，事后无法区分模型是高置信决策还是微弱平局；
3. **执行事件粒度不足**：反手调仓被当作单步黑盒，缺乏平旧仓与开新仓的独立 execution leg，涨跌停拒绝或部分成交无法与前后账户状态精准对账；
4. **业务日期归属混乱**：夜盘时段若按自然日切分会导致同一交易日的数据被割裂，若按固定时钟猜测又可能因节假日调整而产生错归；
5. **部分输出污染正式目录**：回测或校验中途出错若留下残缺的日度文件，会给后续分析造成严重误导。

## Considered Options

- **选项 1：从旧实验产物向后推测/重构三类记录**：
  从现有的 `micro_action_history.npy` 和 `total_asset_history.npy` 逆向估算缺失的推断事实与执行事件。
  *缺陷*：违背真实审计原则；旧产物已丢失的 Q 值、路由概率和执行明细无法被如实还原，任何推测都属于伪造数据。
- **选项 2：追加写入三记录证据链 + 显式 TradingDay + 暂存校验原子发布（选中）**：
  1. **三记录不可变契约**：
     - **Prediction Record**：仅在真实模型推断时产生，记录 short/flat/long Action Values（明确标注为动作价值而非盈利概率）、margin、路由证据、所选动作及模型/特征/参数版本；warm-up、动作持续及规则风控不伪造 Prediction Record；
     - **Trade Record**：每个执行 leg 或尝试均独立成条，记录请求与实际仓位、变动量、事件类型、执行状态、成交价、手续费、已实现盈亏、滑点证据、决策原因，以及连接前后账户快照的 Snapshot ID；反手拆解为平仓与开仓两 leg 并共享 Decision ID；
     - **Account Record**：包含 step 0 初始快照及每步 step 后的快照，全周期 append-only 永不重置，记录钱包余额、未实现盈亏、动态权益、保证金、持仓、暴露、峰值权益与回撤；
  2. **确定性标识符体系**：
     - Prediction ID、Decision ID、Trade ID、Account Snapshot ID 均为 `(run_id, contract, step, leg/kind)` 的确定性函数，多次诊断运行生成完全一致的关联键；
  3. **显式 TradingDay 业务日期归属**：
     - 必须从行情数据的 `trading_day` 列或显式映射文件中获取，严禁采用自然日期或固定夜盘时钟规则臆测；
  4. **独立合约钱包口径**：
     - 账户范围明确为 `independent_contract_wallet`，各合约账户独立记账，不与组合共享资金池混淆；
  5. **严格暂存校验与全量原子发布**：
     - 所有日度分区文件先在 staging 目录生成，依次完成主键唯一性、外键完整性、有限数值、TradingDay 覆盖、`equity = wallet_balance + unrealized_pnl` 权益恒等式以及奖励与净值变化对账；
     - 校验全部通过后才原子发布至正式输出目录并写入根级 `audit_manifest.json`；任何失败立即中止并清理暂存，绝不残留部分正式分区。

## Consequences

- **正面收益**：
  - **证据链严密闭环**：形成“推断输入/输出 $\to$ 决策/规则 $\to$ 执行 leg $\to$ 账户前后快照”的可对账闭环，彻底厘清收益与磨损的真实来源；
  - **杜绝数据污染与脑补**：缺失事实直接 fail-fast，杜绝从旧产物脑补；原子发布确保正式产物 100% 可靠；
  - **概念清晰规范**：明确将 Q 值表述为 Action Value，杜绝概率误读；显式指出未构建日度收盘未来预测器。
- **约束与代价**：
  - 高层回测在仿真过程中需额外保存审计级事件与快照中间件；
  - 仅支持具备完整审计输入的新回测，无法为旧版历史回测直接补齐。
