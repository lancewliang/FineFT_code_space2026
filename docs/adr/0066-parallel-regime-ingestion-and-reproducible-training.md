# 多进程体制分片入池与训练复现

主进程当前逐条构造经验身份、查重及分配槽位，再批量写入 GPU。用户经设计访谈确认采用按体制格独占的多个 CPU 入池进程，配合有界、确定顺序的流式处理，分担主进程串行瓶颈；最终 GPU 经验池仍由主进程统一写入。本文记录已接受的设计，尚不表示实现、复现验证或性能验收已经完成。

## 用户已确认

- 接受新旧实现保留的具体经验不同。同一机器、同一软件版本、同一数据与代码/配置/种子下，要求逐轮经验池内容和最终模型权重完全相同；不以指标接近替代，也不承诺跨硬件或软件版本逐位一致。比较数值内容，不比较运行耗时、日志时间戳或序列化文件的附带差异。
- 保留单个 GPU 写入者，由训练主进程批量提交经验张量；最终经验池继续驻留 GPU。
- 性能验收以完整训练轮次耗时为主，不以某一去重内核或入池局部吞吐替代。
- 一个体制入池分片对应一个独立、常驻的 CPU 入池进程，进程数跟随逻辑分片数；当前 3×3 体制格对应 9 个入池进程。用户明确选定此方案，不再比较 4 个进程的默认配置。
- 首版采用有界批次队列传输紧凑数值批次，不传重复的宽行情状态。若端到端测量证明 IPC 成为瓶颈，再考虑共享内存暂存区；各进程只管理所属格的 CPU 去重/保留元数据，不复制完整 GPU 池。
- 按 Q4 推荐实施复现控制：总种子按任务身份、体制格及采样器用途派生独立随机流，并固定输入/提交顺序；不以 PID、队列到达顺序或所有子进程复用相同随机序列决定训练结果。探索、预训练、经验采样及 GPU 更新均纳入核查与验证，确定性配置的性能成本计入整轮对照。
- 采用有界重排后的流式入池，使探索与入池重叠；不等待整轮探索结束后才开始去重。所有分片及其 GPU 写入完成后才进入本轮参数更新。
- 入池进程异常时，首版 Fail-fast 停止本次运行并清理相关进程与队列；不静默丢弃分片、重新设种子后续跑或自动恢复半完成状态。
- 性能验收目标为稳态完整轮次中位耗时至少下降 20%，且复现检查通过；这是待测目标，不是已经获得的加速结论。

## 沿用的保留规则

沿用 [ADR-0065](0065-n-step-discount-and-bounded-holding-context-replay.md)：精确 float32 模型可见上下文、正负零规范化、拒绝非有限身份字段、同组最多 4 种后续、超额随机轮换、格内 FIFO、索引随驻留容量有界、淘汰结果可重新入选及现有分格采样。暂不引入粗化身份、全历史去重或优先经验回放。

## 已核查的复现性缺口

- 探索任务通过共享任务队列动态分配；当前任务消息和 worker 配置未绑定任务级随机种子，epsilon 探索调用进程全局 NumPy RNG。
- 探索结果按队列到达顺序收集，并按满 16 个结果或队列暂空切微批次；微批次内按 df 排序不能消除跨批次的到达顺序差异。
- 9 格共用一个保留 RNG；仅给各进程设置相同 seed 既不能固定到达顺序，也会让各进程重复同一段随机序列。
- 预训练收集结果也按到达顺序写入；经验采样使用全局 NumPy 或 PyTorch RNG，需要避免无关随机调用改变采样流。
- 当前只有部分 CUDA 确定性设置，尚未验证完整更新路径在严格确定性模式下的支持情况；不能由现有配置推断跨环境逐位复现。

## 状态归属与数据流

1. 共享市场数据包继续只读共享。探索进程回传紧凑轨迹；一次探索任务可以跨多个体制格，协调器按行级体制标签批量分流，不能把整个任务误当成单个分片。
2. 每个入池进程独占所属格的经验组索引、后续变体、槽位/FIFO 游标、替换随机流与统计计数。主进程不再逐条构造去重键、执行查重或作槽位保留决策。
3. 分片返回批量的目标槽位、行情坐标及动态经验字段。主进程基于共享行情批量还原状态并提交 GPU；保留现有训练采样接口及 GPU 张量布局，避免在协调器重新引入逐条宽状态拼接。
4. 批次携带轮次、分片和单调提交序号；同一格的槽位写入保持先后顺序，防止旧批次覆盖已重用槽位的新内容。不同格的 GPU 提交先后不参与去重或随机决策。

## 复现与有界流式协议

- 为训练任务表定义稳定编号，按轮次、任务编号、轨迹步序确定每格输入顺序；批次边界由固定配置和逻辑序号决定，不由队列暂空、到达时间或定时刷新决定。这里定义新实现的确定顺序，不试图复现旧实现本身随完成时序变化的入池排列。
- 探索随机流绑定稳定任务身份，例如总种子、轮次、df、context、初始动作；保留随机流绑定体制格；训练采样器持有独立随机流。使用稳定的种子派生约定并记录版本，避免依赖 Python 进程随机化的 hash、PID 或 worker 分配顺序。
- 预训练也固定收集提交顺序和采样随机流。GPU 更新验证严格确定性设置及算子支持；遇到不支持的非确定性算子应明确失败，不以静默放宽确定性通过验收。记录数据、代码、配置及运行环境身份。
- 限制在途探索任务与乱序结果缓存，并限制输入/输出批次容量；容量预算考虑记录数和字节量，防止少数长轨迹使消息数量上限失去内存约束作用。各上限固定、可观测并记录到运行配置。
- 任务完成标记明确任务身份；各分片具有连续任务水位，即使某个任务没有该格经验也能确认已经越过该任务。轮末各格确认最后水位、已发批次数与完成状态，主进程确认所有预期批次已提交 GPU 后才开始训练。
- 协调器交错派发任务、收集乱序结果及公平排空分片输出；不得在放满有界输入队列时停止收集结果，也不得只等待一个格而不服务其他格。队列暂空不表示任务、分片或轮次已经完成。
- 检测异常退出、错误消息、缺失完成标记及协议序号错误，按 Fail-fast 停止并回收资源。进程重启和完整索引/RNG/在途批次恢复不属于首版功能。

## 验收与比较基线

- 建立遵守同一确定性顺序、每格随机流及 ADR-0065 规则的串行参考实现；与 9 进程实现使用相同初始状态、数据、探索任务、种子、训练更新次数及 GPU 确定性设置。旧到达顺序实现的历史耗时只能作背景，不能单独充当等价性基线。
- 在串行参考实现与并行实现之间比较经验张量、槽位/身份索引、保留计数和后续采样结果；重复完整运行比较逐轮经验内容、损失与最终模型权重，避免仅验证固定输入去重函数。
- 覆盖同组第 5 种后续、完全相同转移的元数据刷新、格满 FIFO、被淘汰结果重新出现、无某格样本的任务、结果乱序与队列背压。注入子进程失败以验证能报错退出，且不会遗留阻塞或僵尸进程。
- 用一致的预热方式和多个连续完整轮次进行配对测量，覆盖经验池已满后的替换负载。完整轮次计入探索、协调与入池、GPU 提交、经验池快照、全部参数更新、权重同步及模型保存；后台评测使用相同配置，并在比较窗口结束时计入未完成评测的收尾。
- 验收要求并行方案稳态整轮中位耗时不高于串行基线的 80%，同时复现检查通过；报告样本量、耗时分布、峰值内存、队列积压和一次性进程启动/关闭成本。局部入池提速不得替代整轮达标。
- 若目标未达成，按实测归因继续优化或重新讨论设计，不通过减少训练任务、更新次数或降低复现要求凑足加速比例。

本设计延续 ADR-0052 的紧凑轨迹与批量写入目标，调整其“所有去重由主进程完成”的职责分配。ADR-0065 的经验等价关系与保留规则继续适用；具体保留轨迹不要求与旧共享随机流逐槽位一致。具体性能改进及端到端复现均待实现与对照验证。
