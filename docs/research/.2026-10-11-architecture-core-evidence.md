# DiHFT 核心源码研究证据（供完整架构文档整合）

研究日期：2026-10-11。范围：模型、低层训练、VAE、选优、高层路由。证据来自当前工作区源码；未运行训练、回测或测试。下列路径相对仓库根目录，行号为本次读取时位置。

## 1. 边界与必须纠正的旧描述

- 不能将“4×4 专家网格”写成全系统固定规格：selector CLI 的 `num_labels` 默认 4，但 `fu10` VAE 脚本 `LABEL_COUNT=3`、选优脚本 `NUM_LABELS=3`，实际主线为每轴三个 VAE、九个装配槽；路由从 selection manifest 读取轴数与 slot_count。训练候选网络数 `N`、replay 九格、最终专家槽数是不同概念。[证据：FineFT/script/train/DiHFT/low_level/VAE_util_fu_10.sh:10；FineFT/script/analysis/pick_agent/low_level_fu_10.sh:16；FineFT/RL/DiHFT/high_level/vae_routing_util.py:800；FineFT/RL/DiHFT/low_level/parallel_weight_advantage_pretrain.py:974]
- VAE 类构造器默认 `Z_DIM=10, hidden_dims=[500,200]`，但训练与路由 CLI 都实际传入 `z_dim=512, hidden_dims=[4096,2048,1024,1024]`。不能把类示例默认描述为实际训练架构；`fu10` VAE shell 未覆盖这些值，覆盖 epochs=500。[证据：FineFT/RL/DiHFT/VAE/vae.py:40；FineFT/RL/DiHFT/VAE/main.py:137；FineFT/RL/DiHFT/high_level/vae_routing_util.py:208；FineFT/script/train/DiHFT/low_level/VAE_util_fu_10.sh:59]
- VAE 重参数化实际使用 `torch.rand_like(std)` 的均匀噪声，不是标准正态 `randn_like`；当前 `estimate_log_px` 是负训练损失（重构 NLL 加 KL）的评分，不应声称精确边际对数似然。模型推断依然通过随机重参数化。[证据：FineFT/RL/DiHFT/VAE/vae.py:79、96、107、129]
- selector 风险门控阈值必须区分类与 CLI：`SelectionConfig.min_positive_contract_ratio=0.40`，CLI 为 0.60；LCB z 默认 0，因此默认 LCB 等于均值；收益门控指标为 `reward_sum/step_count`，不是账户收益百分比。最差初始仓位阈值按 volatility label 可为 -1/-3/-5；不能解释成 -100%/-300%/-500% 账户回撤。[证据：FineFT/analysis/pick_agent/FineFT_two_dimensional_agent_selector.py:76、954、1017、1089、1745]
- 默认 joint coverage 不足可以按 slope marginal 选优，而非一概空仓；`fu10` shell 明确 `MISSING_JOINT_POLICY=empty_model`，这是主线实验配置。[证据：FineFT/analysis/pick_agent/FineFT_two_dimensional_agent_selector.py:1190；FineFT/script/analysis/pick_agent/low_level_fu_10.sh:26]
- `AGENTS.md` 是修改准则，不代表现有代码已全部符合。核心源码仍有兼容入口、fallback、`isinstance`；文档不应将“没有兼容层/防御性访问”陈述为当前已完成事实。[例：FineFT/RL/DiHFT/low_level/parallel_weight_advantage_pretrain.py:59、99、1128；FineFT/RL/DiHFT/high_level/vae_routing_util.py:583]

## 2. 低层网络与训练调用链

1. `Qnet` 接受 state、time、previous_action、avaliable_action、trading_info，前四个特征分支分别映射后拼接，再经 fc2/out；action mask 以 `(mask-1)*1e12` 加入最终 Q。`ensemble_Qnet` 为独立 Qnet 的 ModuleList，输出 `[B,N,A]`。[证据：FineFT/model/low_level.py:12、28、50、75]
2. 并行训练入口 `parallel_weight_advantage_pretrain.Weighted_Contexts_DQN` 加载 `rl_state_features.npy`、保证金字典及 `train/slice/df_*.feather`（目录不存在时兼容 train 根目录）；创建 eval_net、target_net、Adam、SmoothL1 loss。动作总数为 `(position_choices-1)*len(leverage_choices)+1`，position_list 由 max_holding_number 等分，不能固定写成 [-1,1] 的实际交易数量。[证据：FineFT/RL/DiHFT/low_level/parallel_weight_advantage_pretrain.py:59、737、790、812、848]
3. `train()`：创建预训练经验池和 GPURegimeStratifiedReplayBuffer → DP Q-table 诊断及 cache 扩充 → 加载 pretrain_model.pkl 或 `run_exhaustive_warmup` → 清空预训练 buffer → `run_parallel_diverse_training`。当前预训练后 `evaluates(...)` 整段已注释，不宜画成必执行步骤。[证据：FineFT/RL/DiHFT/low_level/parallel_weight_advantage_pretrain.py:954、984、1026、1045、1071、1107]
4. warmup 支持完整轨迹收集与持久化 buffer；`pretrain_epoch=0` 跳过网络更新，非“永远必做预训练”。并行入口默认 pretrain_epoch=0、load_pretrain_model=True，脚本须显式给出符合实验目标的配置。[证据：FineFT/RL/DiHFT/low_level/parallel_pretrain.py:505、634、690；FineFT/RL/DiHFT/low_level/parallel_weight_advantage_pretrain.py:466、510]
5. 多样化每 epoch 的实际主序列是探索完整轨迹 → 保存 `buffer_diverse.pkl` → 激活课程体制子集训练 → 保存 `weights_advantage_pretrain/epoch_{index+1}/trained_model.pkl`（具体构造见 build_epoch_model_path）→ 按 eval_interval 提交后台贪心评估。GPU 训练与 CPU worker 数据交换通过 SharedMarketDataPack/SharedInferenceManager 及 worker 基础设施完成。[证据：FineFT/RL/DiHFT/low_level/parallel_diverse_train.py:903、1644、1782、1818、1890、1931；FineFT/RL/DiHFT/low_level/shared_data_manager.py；FineFT/RL/DiHFT/low_level/shared_model_manager.py]
6. 训练 replay 是 3×3 九格。当前课程 **六阶段**：`[8]`、`[2,5,8]`、`[1,4,7]`、`[0,3,6]`、`[0,4,8]`、全部九格；每个 block 默认三 epoch，所以完整首轮至少 18 epoch。语义 key 含 state hash、previous_action、action、仓位方向、持仓时长 bucket。分格预分配张量、FIFO 配额、去重索引是实现基础。[证据：FineFT/RL/util/regime_stratified_replay_buffer.py:13、24、83、156；FineFT/RL/DiHFT/low_level/parallel_weight_advantage_pretrain.py:782]
7. 参数衰减有课程 block 语义：epsilon/ada 可在各阶段重新衰减，smooth_decay 时初幅按 0.5^phase 缩小；不是整段训练唯一线性退火。六 block 后各参数落到最小值。[证据：FineFT/RL/DiHFT/low_level/parallel_diverse_train.py:662]
8. 损失：warmup 为逐 learner SmoothL1 TD 总和的 batch mean，加 learner→expert 的加权 KL；diverse 为 `[B,N,N]` 跨 learner-target Huber TD 矩阵，经固定 index 邻域矩阵加权，**仍有 `ada*KL`**。KL 使用原 Q 值 log_softmax，没有独立 softmax 温度参数。不能将 diverse 写成只优化 TD 或无监督自发分化保证。[证据：FineFT/RL/DiHFT/low_level/weight_advantage_pretrain.py:523、540、585、888；FineFT/RL/DiHFT/low_level/parallel_pretrain.py:707；FineFT/RL/DiHFT/low_level/parallel_diverse_train.py:2081]
9. 训练末尾“best model”按每个 epoch 返回的最后一次 total_loss 更新，不等于验证集最优收益模型；它与后续二维验证选优分属两层。`AsyncGreedyEvaluator` 会持有模型快照，训练结束 wait_all/shutdown。[证据：FineFT/RL/DiHFT/low_level/parallel_diverse_train.py:549、588、849、1954、1974]

## 3. 低层验证与二维装配

- `test_agent_index.weighted_trader` 对验证切片遍历 label、初始动作、候选 subnetwork，保存 `analysis_result.npy/csv` 与逐步 trading_details；候选 identity 为 epoch 与 bin_index。selector 将 slope/volatility 边际 CSV 与逐步联合标签对齐，先剔除不完整候选，计算 marginal、joint 指标再 gate/rank/select。[证据：FineFT/RL/DiHFT/low_level/test_agent_index.py:617、764、1165；FineFT/analysis/pick_agent/FineFT_two_dimensional_agent_selector.py:364、438、614、660、746]
- 聚合顺序：contract+initial_action 先 reward_sum/step_count；再对 initial actions 求 contract return；可按 step 加权或 contract 等权求均值，计算跨合约正收益比例和标准误；最差初始仓位为各 initial_action 跨合约聚合值的最小值。LCB 使用 configured z。[证据：FineFT/analysis/pick_agent/FineFT_two_dimensional_agent_selector.py:954]
- 槽位 id 为 `volatility_index*K+slope_index`。合格 joint 排序按 eligible、pair_score、mean_lcb 降序、epoch/bin升序；缺少 joint 按配置选择 slope marginal 或 empty_model。[证据：FineFT/analysis/pick_agent/FineFT_two_dimensional_agent_selector.py:1104]
- 输出四张 CSV（marginal、joint、rankings、selection）+ manifest JSON + `model.pth`。装配从各 checkpoint 精确读取 `qnet_list.{bin_index}.`；空槽参数置零，仅 flat action 输出 bias=1。路由另读 manifest 主动防守，不依赖空槽网络推断。[证据：FineFT/analysis/pick_agent/FineFT_two_dimensional_agent_selector.py:325、1643；FineFT/RL/DiHFT/high_level/vae_routing_util.py:1380]

## 4. VAE 与路由信号

- `merge_vae_train` 按 axis/label 从各合约发现二维数组，拼接训练数组并保存 train manifest；Piplineruner 支持 `--train` 和 `--analyze-only`，训练产物按 experiment/axis/label 分目录。下游模型维度来自三个 feature list 的实际长度。[证据：FineFT/RL/DiHFT/VAE/merge_vae_train.py:44、70；FineFT/RL/DiHFT/VAE/main.py:246、278、327；FineFT/script/train/DiHFT/low_level/VAE_util_fu_10.sh:52]
- NLL decoder 输出经过上下界 softclip，训练 loss 为重构 Gaussian NLL + KL。checkpoint 为周期性 epoch `.pth` 和 `model_latest.pth`；并非验证 early stopping 自动选最优 VAE。[证据：FineFT/RL/DiHFT/VAE/vae.py:107、170]
- 路由分别加载 slope/volatility 的每个 label 的 model_latest 与 id_logpx；对当前状态得到负 loss，再在该模型训练参考分数分布上计算经验分位数。每轴每 label 滚动 deque 以 gamma 指数加权平均，这些 weights 是经验分位数平滑值，不是校准过的类别概率。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:975、1171、1183、1212]
- 预计算路径生成 `[T,2*K]` float32 合约分位数并在多次 trial 复用，可跳过 VAE 在线加载。缓存完整性当前主要看目标目录每个合约 npy 是否存在；文档不应声称内容哈希或模型/feature/version 自动失效。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:441、470、1016]

## 5. 路由、安全优先级、指标与参数恢复

- router 构造必须有可装配 manifest；低层模型从 manifest.artifacts.model_assembly 加载。默认 eval_stage=valid；final entry 改成 test，并自动寻找参数文件、Optuna CSV 和 selection manifest。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:793、968；FineFT/RL/DiHFT/high_level/vae_routing_final_result_macro_action.py:17]
- absolute gating：两轴 max 平滑分位数均越阈值才交易；已有仓位时门槛乘 hysteresis_exit_ratio。hierarchical gating：先两轴绝对 OOD 下限，再对归一化 weights 的 top1-top2 margin 门控；并未在该实现套用迟滞。[证据：FineFT/RL/DiHFT/high_level/gating/absolute_gating.py:31；FineFT/RL/DiHFT/high_level/gating/hierarchical_gating.py:34]
- `get_action` 顺序：维护止损生命周期 → 已熔断暂停 → 仓位浮亏/名义货值硬止损 → 可选非主力防守 → VAE gating → empty slot 防守 → persistence 或 policy inference → 同向冷静期拦截。persistence 只持久化非 flat 动作，action mask 失效打断；门控/风控每步仍执行。默认 persistence=3、止损=.015、cooldown=12、连续两次止损、熔断72步（-1永久）。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:156、162、168、174、180、1266、1272]
- 非主力防守依赖 `rl_state_features` 中 `prev_day_contract_role_tier` 列是否存在；当前代码该 index 不存在则不触发此防守。应记录输入契约限制，不能称开关开了必然有效。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:885、1349]
- 合约起始先防守运行 max(axis_window_lengths) 步建立滚动窗口；各合约 reset 独立状态，并非共享同一账户跨合约净值回放。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:837、1034、1461、1680、1760]
- 单合约 return_rate = reward_sum / calculate_required_money；multi-contract router `test()` 的优化目标 = portfolio_return_rate × win_rate，portfolio_return_rate = 全合约 reward_sum 总和 / (initial_wallet_balance × traded_count)，无 traded 时使用全部合约数；win_rate 分母为所有合约。另一个历史文件字段 `'return rate'` 为 ending asset / initial wallet。不能把这些口径混称统一收益率。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:1544、1621、1718]
- 根目录 history npy/csv 来自复制第一个合约；组合摘要在 contract_results.csv 与聚合 trading_info.npy。不能将根目录历史当组合权益时序。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:1707]
- 参数恢复不存在统一 CLI 优先级：双轴 window/gamma/threshold 在 CLI 非 None 时优先；gating strategy/OOD/margin/hysteresis 可被 Optuna CSV，再被参数文件字符串覆盖。函数完全不恢复 action_persistence、初始资金、非主力开关、三级止损设置，所以 fu10 搜索/终测这些显式差异真实保留。[证据：FineFT/RL/DiHFT/high_level/vae_routing_util.py:583-718]
- Optuna 先一次预计算，再 spawn workers 共享 SQLite；每个 trial 无 artifacts，最优 trial 重放一次保存 canonical artifacts。每次 `create_study_storage` **删除已存在 optuna_study.db**，不是恢复续跑。device 根据可用 CUDA 决定，不能把 n_workers help 的“CPU”当实际固定机制。[证据：FineFT/RL/DiHFT/high_level/vae_routing_optuna.py:401、420、448、509；FineFT/RL/DiHFT/high_level/vae_routing_util.py:789]
- final entry 在 test() 后调用 TradingDiagnosticsCalculator；该调用目前 contract_unit=10.0 硬编码，不可直接泛化成任意品种都已配置化。[证据：FineFT/RL/DiHFT/high_level/vae_routing_final_result_macro_action.py:78-101]
