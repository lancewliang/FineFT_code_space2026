# 冻结基线入场Q值与执行对账：目前没有发现明确的错误开仓

## 结论

核对冻结valid中的77个持仓回合后，没有发现预测、路由和成交之间的明确错配，也没有发现模型推荐方向与实际开仓方向相反的记录。每笔开仓均能按同一合约、同一步号连回预测记录；路由查询专家与预测归属专家一致；选中动作可用、路由推荐动作与预测动作一致，实际开仓方向也与该动作一致。计数均为77/77。

Q值对后续净收益只有很弱的描述性关系，不能据此识别出可预测的“错误开仓”。原始Q差距与净收益Spearman相关为0.182；在每位专家内部转换成百分位后为0.192。按专家分别看，样本较多的slot 6相关为+0.355（24笔），slot 7为-0.471（16笔），slot 8接近零（-0.050，9笔），方向不一致。逐个剔除合约后，专家内百分位相关在+0.152到+0.258间，虽都为正，但幅度小、样本仍来自同一段valid，不能视作可靠的跨行情预测力。

因此，当前证据不支持“开仓Q差距低就是错误入场”，也不支持用Q阈值直接筛掉交易。可以确认的是，模型预测、路由与成交日志互相对得上；目前不能从这些日志证明亏损开仓在入场当时可预见。

## 数据与计算

- 冻结基线：`7620ac5ca9979f71bd0152761fc593693546dd8d02b61b6829a8d7c474db02eb`，仅使用 `valid/main_sub`。
- 77个回合来自已有 `entry_features.csv`；逐笔按 `entry_decision` 合并 `audit_predictions.json`、`audit_routing.json`、`audit_trades.json`。
- 对每笔交易，定义推荐方向相对flat的Q优势为 `Q(实际方向) - Q(flat)`。不同专家的Q绝对值不可直接比较，因此额外在各专家内部计算Q差距百分位及标准化值。
- 收益使用已有回合的扣费净收益 `net_pnl`。没有训练模型、搜索门槛或使用test数据。
- 可重跑脚本：[`run_q_audit.py`](fu_10min_cause_20261028/q_audit/run_q_audit.py)。逐笔合并表：[`entry_prediction_trade_join.csv`](fu_10min_cause_20261028/q_audit/entry_prediction_trade_join.csv)。汇总：[`summary.json`](fu_10min_cause_20261028/q_audit/summary.json)。

## 具体发现

### 日志链条没有发现开仓错配

| 核对项 | 结果 |
|---|---:|
| 持仓回合数 | 77 |
| 每笔都有对应预测记录 | 77/77 |
| 预测步号等于开仓步号 | 77/77 |
| 预测合约等于开仓合约 | 77/77 |
| 路由查询专家等于预测专家 | 77/77 |
| 路由预测ID等于预测记录ID | 77/77 |
| 路由推荐动作等于预测选中动作 | 77/77 |
| 预测选中动作当时可用 | 77/77 |
| 成交存在且方向与持仓记录一致 | 77/77 |

`audit_trades`开仓成交记录也带有对应预测ID，77/77均能关联。故这批数据没有显示“拿错专家的Q值”“平仓步当作开仓步”“信号做多而成交做空”等日志级错误。

### Q差距不能可靠地区分好坏开仓

77笔中43笔净盈利、34笔净亏损。赢家的平均入场Q差距为14.73，亏家为14.93，几乎相同。推荐方向相对flat的Q优势与净收益相关系数同样很弱：

| 算法 | 与净收益的Spearman相关 |
|---|---:|
| 直接比较Q差距 | +0.182 |
| 先在同一专家内部排百分位 | +0.192 |
| 专家内标准化后 | +0.132 |

把每位专家内部的Q差距排名粗分四组，收益也没有随着Q差距稳定上升：最低组20笔的平均净收益约0元/笔，下一组19笔为+23.94元，第三组20笔为+47.00元，最高组18笔反而降到+38.24元。此分组是描述，不是可部署门槛。

同专家样本最多的slot 6与slot 7呈相反关系；有些小样本slot看起来相关较高，也可能由少数交易偶然造成。77笔分散到9位专家和多个合约，现有样本不足以估计稳定的专家内收益预测关系。

### 方向、专家、合约存在差别，但还不能归因为错误信号

- 多单38笔，净收益合计+1,083.99元，胜率55.3%；空单39笔，+996.75元，胜率56.4%。没有明显的单边方向性亏损证据。
- slot 6有24笔、胜率37.5%，平均每笔+14.81元、中位数-6.40元；slot 8有9笔、胜率44.4%、中位数-0.94元。它们值得继续追查，但Q差距在slot 6里反而与收益呈弱正相关，在slot 8里接近零，不能简单说是“低Q导致亏损”。
- 合约和时段的样本数量有限，而且市场走势会同时影响信号与结果。本次没有证明某合约、方向或专家存在可提前识别的系统性错误。

## 对“错误开仓”根因的当前回答

目前可以排除这77笔交易中明显的预测—路由—成交关联错误；不能排除策略对行情判断本身出错。Q值是模型内部的动作价值估计，不是盈利概率。即使当时Q值最高，也不保证扣除费用后盈利；一次亏损也不自动说明入场判断在当时有错。

要继续确认根因，应把同一持仓周期中的入场依据、持仓期间路由/动作变化、止损或规则平仓原因，以及平仓后的再次开仓连成一个生命周期，再对每笔止损做事后行情路径归因。该生命周期分析由本次主任务的其他审计负责；本报告不重复推断，也不把本valid上观察到的差异转换成新阈值。

## 证据边界

这是同一个历史valid上的77个回合描述性审计；按合约留一后相关仍然来自同一时期。它不是独立样本检验，也未使用完全未触碰的数据。因此结论限于“日志链条正确；Q对本样本净收益没有稳定区分力；明确错误开仓尚未证实”。

## 与持仓生命周期追踪结果的独立对账

另行核对主任务保存的 `runtime_diagnosis_summary.json`、两个 episode diagnosis 表和逐步trace。逐步trace验证结果显示，baseline重放对应77回合，候选组合对应76回合；两组各自记录的29,125个决策都与对应的逐步盈亏重放对得上。这里的候选是同一valid上选出的研究方案，不是独立样本。

在baseline，11个硬止损回合之前，同一合约的上一持仓回合都是 `POLICY_INFERENCE` 退出；其中上一回合与止损回合方向相反8次（之前为多5次、空6次）。这表示同合约的回合顺序里，止损发生在一次普通模型平仓之后，常见情况是方向翻转；它不代表已证明翻转本身导致止损，也不一定是全组合里紧挨着发生的两笔交易。对同方向连续持仓回合的定义按合约分别排序，没有跨合约配对。baseline中紧随某次止损的6个同方向回合合计净收益+622.36元，其中5个净值为正、1个为负；候选组合对应6个合计+436.33元，也是5个正、1个负。两组的这6回合各有1个到valid结束仍未平仓，其净收益按期末账户权益变化计入。因此不能说六笔都已实现盈利。两组这些同方向后续回合均没有再次触发硬止损。

亏损持仓内的真实模型重询记录也值得追踪：baseline纳入统计的96次“仍持仓且未实现亏损时的真实专家查询”中，模型Q的argmax 96次都仍为当前持仓方向；候选组合为77/77。计数来自查询时真实的仓位、亏损状态和实际被查询专家的Q值，不是事后影子查询。这说明模型在已出现浮亏时通常还建议继续持有，风险硬止损后来负责强制平仓。但这仍不能证明初次入场有错：它描述的是持仓后的判断，也没有测试“提前退出”反事实会否更赚钱。

硬止损步没有真实的低层策略查询；追踪脚本保存调用前的活动专家槽，并在当步决策完成后用同一个状态/输入、同一个槽位额外计算影子Q。逐行核对显示baseline止损11/11、组合10/10的 `q_inspection_slot` 都等于当步 `active_slot_before`，且 `queried_slot` 为空、`q_is_shadow=true`。所以没有发现影子Q取错活动专家的证据。影子动作只是“如果当时没有风险强制平仓，该专家在这个状态下偏好的可用动作”，不是实际发出的信号，更不是持有后的收益预测。

原统计字段 `last6_shadow_flat_steps` 的窗口条件是 `step > stop_step - 6`，而被统计的记录又只包括 `ACTION_PERSISTENCE` 影子Q，不包括止损步。因此它实际上只涵盖止损前5根bar。若严格改成止损前6根bar，即 `[stop_step-6, stop_step)`，baseline在11个止损中有1个回合出现持久期影子Q选择flat；组合为2/10（fu2501第2274步止损、fu2505第3349步止损）。这处窗口边界应在汇报中修正。

这些生命周期结果与本报告的Q审计可以同时成立：入场时模型方向和成交方向一一吻合、Q差距不能稳定区分赢家与输家；而止损前模型在亏损时段仍多次重询并保持同方向。后者给出更具体的持仓管理线索，但尚未证明“原始错误入场”的因果根因。判断它是否可修复，需要先提出一条不依赖当前valid调出来的新假设，再用未触碰的后续时间段评估。
