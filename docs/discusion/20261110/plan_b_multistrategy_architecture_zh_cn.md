**范围：只讨论方案 B；不包含具体实现代码。**

## 0. 依据、状态与阅读约定

本说明以《10 分钟级商品期货强化学习交易：多尺度特征、门控与子 Agent 架构设计》中的方案 B 为主依据。[S1，§十二] 该方案允许高层在不同策略之间动态选择，各子 Agent 自己负责开仓、持仓和普通退出；长期上涨并不自动排除短期均值回归机会。

现有 FineFT/DiHFT 工程说明用于识别可复用组件；低层 Agent 研究用于识别状态与奖励缺口；FineFT 论文用于说明集成训练、能力边界与启发式路由的来源。[S2；S3；S4]

**以下组件划分、数据契约、训练分段、交接状态机与实施顺序属于本版提出的设计，不表示现有代码已经实现，也不是已经验证有效的交易结论。** 本次没有审查实际代码仓库、配置快照、逐笔成交或回测账本，不认证材料中的收益、胜率、延迟和风险保证。具体窗口、阈值、仓位与模型复杂度均须样本外验证。

材料存在需要实施前核对的版本差异：S2 的模型选择描述使用 4×4 槽位，但部分奖励逻辑使用 `regime_grid_id % 3`；S2 介绍默认 9 档动作，S3 的个别执行分析使用 3 档动作。不能把这些文字直接拼接成生产接口。[S2，§3.2、§3.5、§6.2；S3，§2.4]

## 1. 目标、非目标与第一版边界

### 1.1 目标

在每 10 分钟观察和决策的前提下，根据当前可获得的信息、专家能力、真实持仓和预估成本，选择最合适的策略，并保留不新开仓的能力。系统优化的是可实现、扣除成本的交易结果及其风险，而不是市场分类准确率、某个专家的训练奖励或路由活跃度。[S1，§二、§七—九]

需要同时回答：现在适合哪类策略；该策略是否允许入场；已有仓位由谁管理；值得为新机会退出旧仓吗；退出是否真正成交；风险要求是否覆盖普通策略；每笔收益和成本归因给谁。

### 1.2 第一版采用的边界

| 议题 | 本版建议 |
|---|---|
| 策略池 | TF、MR 和确定性防御；PB 暂不单独训练 |
| 仓位组织 | 每个合约一个逻辑净仓、一个主动策略管理者；禁止用同时持有独立多空仓绕过该约束 |
| 全账户风险 | 各合约共享账户风险预算；不能各自假设占有全部可用保证金 |
| 门控形式 | 可解释规则基线，之后为冻结专家训练条件效用评分器；第一版不直接做高低层端到端 RL |
| 持仓交接 | 候选策略随时可变；跨策略所有权只能在真实平仓、旧开仓订单处理完成后切换 |
| 强制退出 | 风险事件随时抢占；普通切换须经过显式退出请求，不由标签变化自动触发 |
| 策略输出 | 统一目标仓位意图；只有执行层能够生成真实订单 |
| 部署方式 | 模块化单体或少量进程优先；数据、模型、账本与风控有清晰边界，不预设 50 个微服务 |

### 1.3 不在第一版中解决的事项

多专家同时持有互相独立的虚拟资金账户并直接叠加实盘仓位、带仓跨策略接管、策略在线自主改权重、动态扩大杠杆、独立 PB 专家，以及高层半马尔可夫 RL，均属于后续独立验证项。保留接口不等于默认启用。

## 2. 必须分开的核心概念

| 概念 | 含义 | 不允许的混用 |
|---|---|---|
| `market_regime` | 趋势方向、强度、效率、波动、状态转移及可信度的描述 | 不等于应该交易的策略 |
| `strategy_family` | TF、MR、未来 PB 等交易逻辑类别 | 不等于某个涨跌槽位 |
| `expert_id / expert_version` | 实际策略模型及其固定版本 | 不等于策略类别或市场状态编号 |
| `candidate_strategy` | 门控当前偏好的候选者 | 不等于已有仓位的新管理者 |
| `position_owner` | 对当前实际持仓负责的主动策略 | 不因候选变化自动改变 |
| `risk_mode` | 正常、禁止新增风险、仅减仓、紧急退出等控制状态 | 不宜压缩为一个含义模糊的“防御 Agent” |
| `position_episode_id` | 从实际首次开仓成交到实际完全平仓的经济生命周期 | 不因路由、模型选择或账面标签变化重置 |
| `requested / approved / executed` | 策略请求、风险批准、实际执行结果 | 目标仓位不能冒充实际成交仓位 |

现有市场槽位仍可用于能力评估和诊断，但在方案 B 中只能提供市场上下文。必要时可在每个策略族内部再选专家，不能把 16 个状态槽位直接重新命名成 16 种策略。[S2，§3.5；本版设计]

## 3. 系统总体关系与部署边界

**数据平面：** 原始行情与合约元数据 → 事件标准化与质量检查 → 因果 Bar 与多尺度特征 → 版本化状态快照。

**离线学习平面：** 数据快照与时间切分 → 状态模型和策略族训练 → 专家筛选与冻结 → 样本外反事实回放 → 门控训练与校准 → 完整系统验证 → 发布包。

**在线控制平面：** 状态快照与真实账本 → 市场状态估计和预检查 → 专家候选意图 → 条件效用评分 → 稳定门控 → 所有权状态机 → 持仓管理 → 最终风险裁决 → 执行意图。

**执行反馈平面：** 执行意图 → 订单管理 → 交易接口 → 委托/成交回报 → 对账 → 账户与持仓账本 → 下一轮状态快照。

**横切控制：** 快速风险监控可以中断普通决策；审计、版本管理、漂移监控和恢复机制覆盖全部平面。

依赖方向应单向清晰：专家不直接调用交易接口；门控不直接修改账本；VAE 不直接下平仓单；特征计算不读取未来收益标签；账本只接受确认后的交易事实和授权调整事件。在线与离线共同使用特征定义、动作语义、成本模型、状态转换和风险规则的版本化契约，但分别使用真实与模拟执行适配器。

### 5.2 全链路标识与版本

离线产物至少关联：产物编号、模式版本、实验编号、源数据快照、父产物哈希、拟合截止时间、训练/标签区间及实现版本。对不适用字段应明确标注不适用，而非伪造时间。

在线记录至少关联：账户、合约、交易日、事件时间、信息可用时间、决策时间、决策编号、发布版本、账本快照版本、当前 owner、Episode 编号及原因码。模型版本与特征版本不匹配时禁止新增风险；处理已有仓位使用事先定义的确定性恢复/风险路径，不隐式加载“差不多”的模型。

### 5.3 最关键的六类契约

**特征契约 A06/A10：** 每个特征有单位、窗口计数方式、最短历史、可用时间、计算版本和缺失掩码。训练与在线读取相同顺序。日频/更高周期特征必须明确使用上一根已完成周期，或另行定义可在线复现的未完成周期特征；两者不能混用。

**专家意图 A26：** 包含策略族/版本、候选目标数量或标准化仓位、开仓/加仓/减仓/退出语义、有效期、普通退出依据及必要上下文。原始 Q 值只在其自身动作空间内解释，不直接充当跨专家可比收益。

**门控决定 A27：** 包含当前管理者、候选策略、候选/继续方案效用、净优势、是否满足滞回和驻留、允许的生命周期操作及拒绝原因。它不得偷偷改写实际仓位。

**持仓契约 A25/A28：** 包含实际数量、成交成本、已实现与未实现盈亏、费用、开仓时间、Episode 高水位、当前 owner、挂单占用、冷静期和交接阶段。经纪商分项多空仓及今昨仓等底层事实不可仅用一个净数替代。

**风险契约 A29：** 将合法性、风险预算、仅减仓限制和紧急退出分别表达。降低风险的平仓请求不能被“强趋势禁止反向新增仓位”的规则误伤；但允许发送退出请求不代表市场一定成交。

**执行契约 A30/A31：** 请求、批准、提交、受理、部分成交、撤单中、拒绝、最终成交与对账各是不同事件。模型目标、批准目标、实际成交量都要保留，不能用一个 `previous_action` 代替这三个层次。

## 6. 在线与离线特征工程

### 6.1 保留三流，但不把信息永久隔离

保留 S2 的趋势流、波动率流、微观 RL 决策流，因为不同统计目标需要不同审计方式。[S2，§2] 但三流解耦不等于低层不能接收宏观上下文。建议各流独立计算与编码后，将必要的多尺度状态注入 TF/MR 的输入。低层还必须接收真实持仓、风险模式、挂单和生命周期信息。[S1，§六；本版设计]

VAE 用于市场分布与能力边界证据；策略条件收益模型用于“谁更值得执行”。二者不是同一模型、同一标签，也不应共用同一种筛选指标。

### 6.2 第一轮候选状态

| 特征域 | 候选内容 | 首轮尺度/语义 | 主要用途 |
|---|---|---|---|
| 趋势 | 波动归一化斜率、收益方向、多尺度一致性、趋势效率 ER | 36/144/720 根实际交易 Bar；2016 为后续候选 | 区分方向、强弱和路径效率 |
| 波动 | 短中长波动、短长比值、波动扩张/收缩 | 12/72/432 根实际交易 Bar | 判断风险能级及其变化 |
| 微观 | 近期价格/成交/盘口变化、价差和深度 | 数据可支持的短窗口 | 入场时机、成交约束与成本 |
| MR 机会 | 相对因果均衡锚的标准化偏离、锚的漂移、回归失败证据 | 锚和尺度必须同单位、可因果计算 | 区分“偏离较大”和“值得交易的回归” |
| 持仓 | 真实方向/数量、持有时长、成本、净收益、高水位回吐 | 实际成交生命周期 | 管理已有仓位，而非只预测价格 |
| 控制 | owner、pending 策略、风险模式、挂单、剩余冷静期 | 当前运行状态 | 避免未成交反手、重复开仓和非法交接 |
| 专家可靠性 | 已成熟的历史条件净收益、误差、失败率和覆盖度 | 只能使用当前之前已经完成的结果 | 为门控提供策略能力证据 |

候选趋势/波动窗口继承 S1 的实验建议，不是经本次验证的最优参数。[S1，§二—四] 720 根 10 分钟 Bar 表示 720 根实际交易 Bar，不自动等于若干自然日。必须分别记录交易时间和自然时间；停盘、夜盘、节假日及不同品种日历由 A02 决定。

### 6.3 离线特征流程

原始归档 A01 → 按当时可用时间重放/清洗 → A03 → 先确定 A05 的时间边界 → 依据 A06 计算 A07 → 在允许训练区间审计/选择 A09 → 仅在相同允许区间拟合 A08 → 冻结定义与变换 → 生成各阶段的 A10。

不能先用全历史挑特征、求分位数和缩放，再声明后面的模型训练是样本外。监督特征审计依赖的未来标签也必须受 A05 控制。波动特征不应被只预测带符号方向收益的筛选器一概淘汰；相反，某特征能预测方向也不代表能识别能力边界或改善交易决策。

### 6.4 在线特征流程

新行情事件 → 质量/新鲜度检查 → 更新同合约状态缓冲 → 完成 Bar 时按相同公式更新特征 → 应用冻结 A08 → 联结最新真实账本与订单状态 → 输出带 `available_at` 的 A10/决策快照。

在线可以更新滚动统计与缓存；在线不应未经验证重新拟合中位数、IQR、VAE 参考分布或模型权重。训练模式的“拟合”与推理模式的“更新滚动状态”是两件事。

### 6.5 因果性与冷启动约束

所有输入必须满足信息可用时间不晚于决策时间。使用当前已完成 Bar 的收盘信息后，应在明确建模的后续可成交时点执行，不可无条件按同一收盘价无滑点成交。

不跨合约滚动计算特征，继承 S1 的约束。[S1，§九] 测试期初可以读取决策时本来已经存在的同合约过去行情作预热，不等于允许用测试结果拟合。历史不足的特征必须标记无效；采用禁止新仓或预先验证的缺失模式，不能默默用另一合约历史填补。

双向滤波、全样本峰谷分段及事后识别的市场阶段只可在被明确批准的离线标签/分析路径使用，不可伪装成在线状态。历史数据修订也需保留当时可获得的版本；否则离线和在线并非在看同一份事实。

## 7. 在线决策与推理完整流程

### 7.1 两个时钟，而非一个 10 分钟循环包办全部控制

普通行情观察、专家推理和门控评估按 10 分钟决策时钟执行；委托/成交回报、资金变化和风险事件由事件时钟处理。普通门控可以慢，执行对账和紧急风险不能因为尚未完成下一根 Bar 而被冻结。[S1，§一、§七；本版设计]

若研究数据只有 10 分钟 OHLC，不能声称已经验证盘中止损触发顺序、真实延迟或盘口滑点。需补充更细数据，或明确回测的保守成交假设和无法验证的范围。

### 7.2 一次正常决策的顺序

| 步骤 | 处理 | 输出及约束 |
|---|---|---|
| O01 | 消费新行情、委托和成交回报，完成必要对账 | 先更新真实账本；已发生的成交不能等待模型推理 |
| O02 | 快速检查数据、账户与硬风险 | 紧急风险可取消新增订单并进入退出流程，不等待普通门控 |
| O03 | 确认 Bar 完成和特征历史就绪 | 不使用未来 Bar 或尚未可获得的汇总值 |
| O04 | 固定本轮一致状态与发布版本 | 专家、评分器和门控读取同一基准快照 |
| O05 | 估计市场上下文和策略准入 | 产生 A12 和预检查 A29；分类不直接下单 |
| O06 | 当前 owner 产生持仓管理意图；候选专家产生机会意图 | 候选不是新 owner；未被授权者没有订单权限 |
| O07 | 比较可执行方案的条件净效用 | 已有仓位时需计入旧仓退出、等待和新仓进入的成本及风险 |
| O08 | 应用拒绝交易、滞回、驻留与持仓感知规则 | 得到 A27：保持、等待、申请退出后切换或降低风险 |
| O09 | 所有权状态机验证动作是否可实施 | 尚未确认平仓时，不能给新策略开仓权限 |
| O10 | 持仓管理、利润保护和动作掩码合成候选目标 | 普通保护不能撤销更高级风险限制 |
| O11 | 用最新账户状态完成最终风险校验和风险预占 | 过期授权失效；其他合约的并发新增风险也要计入 |
| O12 | 订单层提交，持续处理后续回报并记录审计 | 实际成交驱动仓位变化和后续交接，不把目标当成交 |

O12 不要求成交在当前函数或当前 Bar 内完成；未完成订单继续参与下一轮状态。后续成交改变快照后，必要时撤销旧的开仓许可或重算目标。

### 7.3 防御状态必须拆开

| 风险模式 | 空仓时 | 已有仓位时 |
|---|---|---|
| `NO_NEW_RISK` | 不新开仓 | 当前 owner 可按既定规则管理、减仓或退出；不允许增加风险 |
| `REDUCE_ONLY` | 维持空仓 | 仅允许持有等待可成交、减仓或平仓，不得扩张敞口 |
| `EMERGENCY_EXIT` | 撤销未结新增订单 | 发出紧急退出请求，持续追踪成交和残余敞口 |
| `RECOVERY_UNCERTAIN` | 暂停新增风险 | 保留真实仓位事实，先查询/对账，再按授权风险政策处置 |

“无新交易机会”不同于“必须立刻清仓”。市场状态略模糊可以提高入场门槛；严重数据/账户/风险事件可以要求退出。不能将所有低置信度都映射成同一个强平开关。

## 8. 持仓所有权与策略切换协议

### 8.1 第一版状态机

| 生命周期状态 | 管理规则 | 允许的下一步 |
|---|---|---|
| `FLAT_READY` | 无实际仓位且无旧的新增风险订单；可选择入场策略 | 进入 OPENING，或继续等待 |
| `OPENING` | 为一个策略预留管理权，处理其开仓订单 | 首次成交后成为 owner；未成交撤销完成后返回空仓 |
| `OWNED` | 当前策略拥有唯一普通管理权 | 持有/减仓/退出；候选变化可进入 SWITCH_PENDING |
| `SWITCH_PENDING` | 新策略只是候选，旧 owner 仍负责已有仓位 | 放弃候选、继续持有，或显式批准退出后切换 |
| `CLOSING` | 处理退出；先撤销可能再次增加旧风险的订单 | 部分平仓继续关闭，不允许新策略开仓 |
| `FLAT_CONFIRMING` | 核验真实多空分项仓位和旧订单，不只看一个净仓数字 | 确认真空仓后进入 FLAT_READY 或规定的 COOLDOWN |
| `COOLDOWN` | 按触发原因限制新的同向/全部开仓 | 条件满足后重新评估，不沿用过期信号 |
| `RECOVERY_UNCERTAIN` | 委托/仓位状态不确定时停止新增风险 | 对账完成后恢复到实际对应状态 |

风险模式是这套状态机之上的控制层，而不是另一个偷偷更换 owner 的策略。因强制退出产生的损益仍归原经济持仓，控制原因另外归因。

### 8.2 两种变化必须区分

**候选变化：** 当前最值得关注的策略从 TF 变为 MR，只改变 `candidate_strategy`，不交易，不重置持仓、不重置高水位。

**所有权切换：** 必须先完成旧仓退出和旧新增订单的处理。第一版在确认真空仓后的下一次允许决策点重新打分，再决定是否启动新策略。它不是“昨天已经决定切 MR，所以不论现在行情怎样都必须开 MR”。

主动退出以切换策略可以成为显式的门控动作，但必须独立评估相对继续持有的净优势，并受普通切换滞回约束。它不同于市场分类发生改变就强制平仓。

### 8.3 一个示例

TF 正持有多仓，短期价格偏离使 MR 提出做空机会。门控先比较继续 TF、等待旧仓正常退出、主动退出后执行 MR 三种方案。MR 只有略高毛收益但不能覆盖往返成本时，保持 TF。

当净优势持续达到经校准的切换门槛，系统申请退出 TF。平仓订单仅部分成交时，仍归 TF 的 Episode，MR 不可开空。只有剩余多仓为零、可能再次开多的旧订单已妥善处理并完成确认，才重新评估 MR。届时机会消失就继续空仓；机会仍存在且风险允许才开 MR。

这仍然是方案 B：长期上涨不会一票否决所有短期 MR 做空机会，但也不会因 MR 信号出现就立即把旧多仓翻空。

### 8.4 为什么第一版不带仓接管

带仓接管并非原理上不可行，但新专家必须在训练中见过别的策略留下的方向、成本、持有时间、高水位、未结订单和风险状态。接管不能把浮亏改成新的开仓基准，也不能洗掉历史回撤。

第一版先采用真实平仓后交接，以降低策略归因、训练分布和执行状态的复杂度。未来增加带仓接管时，应作为独立动作与独立数据分布训练、验证，不能仅把 `expert_id` 改掉。## 9. 策略族定义、专业化与低层训练目标

### 9.1 三类首发策略的契约

| 策略 | 交易逻辑与输入重点 | 普通退出 | 关键约束 |
|---|---|---|---|
| TF 趋势跟随 | 依据多尺度方向、强度、效率和延续证据寻找顺势机会；兼看成本与短期回撤 | 趋势证据失效、收益/风险权衡不再有利、正常减仓 | 不能只因短期噪声频繁反手；也不能把“少换手”解释成拒绝退出 |
| MR 均值回归 | 依据相对可因果计算的均衡锚的偏离及条件回归证据交易 | 回到目标区域、回归假设失效、持仓超时或风险限额触发 | 偏离大不等于安全；禁止无上限逆势加仓，不默认采用摊平亏损 |
| 确定性防御 | 不负责寻找独立收益机会，执行已批准的降低风险政策 | 由风险状态和执行结果决定 | 明确不新开仓、仅减仓、紧急退出；不让 RL 学习是否遵守硬限制 |

TF 与 MR 都需要长短周期和持仓状态，只是对信息的使用方式不同。仅改变随机种子、选择不同涨跌槽位或修改模型名字，不能证明专业化。[S1，§五—六]

PB 是较大趋势内的回调入场逻辑，与押注回到均衡锚的 MR 不同。[S1，§五] 第一版把回调作为 TF 的场景；只有独立 PB 在相同测试条件下产生稳定增量时，再加入正式专家池。

### 9.2 如何在训练中形成专业化

使用策略族规格 A13 同时约束状态重点、开仓候选域、风险预算、示范和样本采样。可以让 TF 更频繁看到趋势延续/回撤场景，让 MR 更频繁看到稳定回归/区间失效场景，但必须保留完整的连续交易过程。

不能只拼接“上涨片段”训练 TF，再把趋势终止后的亏损段丢掉；也不能只在已经确认回归成功的片段训练 MR。专家需要见到假突破、回归失败、趋势反转、流动性变差及持仓进入不适用状态后的退出情形。

若沿用 FineFT 的集成选择性更新，第一阶段建议在同一策略族内部共享和分化，再评估是否需要跨族共享。不同奖励或动作约束的模型不应直接套用未经审查的同一套 Q 误差比较；原论文的市场动态专业化并不等于本版明确的 TF/MR 行为专业化。[S4；本版设计]

### 9.3 必须修改的现有奖励偏好

S2 的非对称换手塑形中，上涨体制下 `new_pos < old_pos` 使用更高惩罚，这同时涉及做空和退出多仓；震荡体制下部分开仓也被提高惩罚。[S2，§6.2] 如果不加区分地复制给 MR，就可能把有用的回归交易和必要退出一起压制。

本版建议先统一真实净收益及硬风险底线，明确区分开仓、加仓、减仓、平仓、反手；再对各策略族的非必要换手进行可控塑形。硬风险退出不应被额外的“维持持仓奖励”覆盖。真实交易成本仍须记账，不能为了让模型愿意止损而把真实费用抹掉。

一个可研究的基础目标为：

\[
r_t^{(k)}=\frac{\Delta E_t^{\mathrm{net}}-\Delta F_t^{\mathrm{external}}}{E_{\mathrm{ref}}}
-\lambda_{\mathrm{turn}}^{(k)}\,\phi_t
-\lambda_{\mathrm{risk}}^{(k)}\,\psi_t.
\]

其中净资产变化已按实际成交口径反映费用和滑点；外部入出金单独剔除；参考资金规模与奖励单位固定声明；后两项是额外的学习偏好，不扣减真实账本。第一轮可仅保留必要的净收益和少量经过检验的塑形，避免同时调很多奖励项。

折扣率、训练片段长度、决策步长、终止条件和动作持久化都影响策略学到的持仓行为。增加 720 根 Bar 特征，不自动等于模型拥有同样长的优化目标。

## 10. 高层门控到底学习什么

### 10.1 不是市场标签，也不是专家原始 Q 值

门控的目标是预测“在当前真实状态下采用某个可执行控制方案，未来一段共同评价期的净效用怎样”。它不应仅学习上涨/下跌/震荡标签，也不应简单选择最近累计收益最高或原始 Q 最大的专家。[S1，§二、§八；本版设计]

定义候选控制方案 `omega`，而非只定义专家编号。空仓时可以比较启动 TF、启动 MR、等待；持仓时可以比较继续当前 owner、等待正常退出、申请退出后启动另一策略。第一版不包含带仓接管方案。

### 10.2 统一净效用评分

建议的评分结构为：

\[
\widehat U_t(\omega)=\widehat\mu^{\mathrm{net}}_{t,H}(\omega)
-\lambda_{\mathrm{tail}}\widehat L_{t,H}(\omega)
-\lambda_{\mathrm{unc}}\widehat\sigma_{t,H}(\omega)
-\lambda_{\mathrm{churn}}I_{\mathrm{control\ change}}(\omega).
\]

`mu_net` 为共同期限 H、共同起始账户/仓位和共同风险口径下的预期净结果；`L` 为约定的下行风险估计；`sigma` 为经留出数据评估的预测误差或不确定性描述，不能直接宣称是有保证的置信区间；最后一项为可选控制复杂度正则，不是真实手续费。

旧仓退出、新仓建立、滑点和费用应已经计入方案净结果。不能在此基础上再扣一遍同样的“切换手续费”。候选标签变化但没有成交时，真实执行成本为零；额外切换正则必须单独显示。

普通切换可要求：新方案相对继续方案的净优势超过阈值、连续若干次确认、普通驻留约束满足，且生命周期状态允许。所有阈值只在校准区间选择。驻留限制的是普通控制权切换，不是风险退出，也不应机械冻结低层正常减仓。

### 10.3 如何使用 VAE

FineFT 的原始方法使用经过参考分布处理的 VAE 分数和启发式路由，并保留保守策略；不是默认端到端训练一个高层 RL。[S4，§4.2—4.3；R1]

方案 B 中保留 VAE 的合适角色是：提供是否接近已见分布的证据、帮助拒绝不可靠的新交易、辅助识别需要风险降级的状态。原始 VAE loss、分位数、策略盈利概率和市场体制后验概率是不同量。两个特征轴应分别处理参考分布，再验证联合控制效果，不能因为都输出一个数字就直接相加或 Softmax 成“可信胜率”。

生成模型在其他领域已有对 OOD 分配更高似然的反例，因此不能把 VAE 高分视为安全证明、低分视为必然灾难；本系统仍需独立账户、仓位、流动性及执行风险控制。[R2] 该研究不是对本系统数据的实证结论，只说明这种保证在一般情况下不成立。

### 10.4 低置信度时不是都清仓

所有入场候选净优势不足时，空仓系统继续等待；已有仓位则由当前 owner 在 `NO_NEW_RISK` 或既定持仓管理规则下处理。只有满足明确的退出规则或风险条件时才发出退出请求。这避免把短时分类摇摆直接变成反复平仓。

## 11. 离线训练、选模与门控标签完整流程

### 11.1 建议的五段时间结构

| 时段 | 用途 | 不得混入的工作 |
|---|---|---|
| D_E：基础训练段 | 拟合特征变换、状态模型、教师/专家候选 | 不读取后续绩效或未来段的统计量来拟合 |
| D_S：专家选择段 | 评估候选、确定策略族专家池并冻结版本 | 不把这里的选择收益报告为最终测试结果 |
| D_G：门控学习段 | 用已经冻结的专家生成样本外回放和门控训练标签 | 专家不能根据 D_G 的表现反复改到最佳后仍称其标签是样本外 |
| D_V：校准段 | 校准评分、拒绝、滞回与普通切换参数，验证完整闭环 | 不把 D_V 再当无偏最终测试 |
| D_T：最终测试段 | 锁定所有版本后评估最终系统 | 不依据结果继续选择窗口、参数、专家或门控 |

以上为设计上的数据角色，不要求机械等长。数据有限时采用前向交叉拟合，但每条门控训练样本都必须由在该样本时点之前已经冻结的专家版本生成。跨合约划分仍要服从全局时间边界，不能用未来日期的另一合约替同一市场提供未来信息。

所有会使用未来结果的标签，其结束时间必须落在允许区间内；边界附近尚未成熟或跨入下一段的标签需剔除或延后使用。LOCO 可以补充未见合约评估，但不能取代严格的时间外推。[S1，§九；本版设计]

| 阶段 | 输入 → 处理 → 输出 | 放行条件 |
|---|---|---|
| L01 数据冻结 | A01/A02 → 清洗、时点对齐、质量报告 → A03/A04 | 可重放，合约/时间/费用口径明确 |
| L02 切分与特征 | A03 → A05/A06/A07 → 训练期审计与拟合 → A08/A09/A10 | 无全样本拟合，离线/在线一致 |
| L03 状态模型 | 允许训练的 A10 → 模型与参考分布拟合 → A11 | 输入、参考分布和拟合截止可追踪 |
| L04 专家训练数据 | A10/A13/A23 → 完整 Episode 与可选教师 → A14/A15 | 路径、风险、动作和执行语义一致 |
| L05 训练候选 | A14/A15 → TF/MR 分族训练 → A16 | 记录数据、配置、种子、损失和异常 |

| L12 发布与观察 | A24 → 影子/受控执行 → A32/A33/A34/A35 | 版本一致、可恢复、可对账、可回滚 |

### 11.3 反事实标签怎样构造

每个决策起点克隆同一份市场可见信息、真实持仓、成本、资金、Episode 高水位、挂单和风险状态。对每个候选方案使用同一环境规则回放未来 H 步，记录净资产变化、下行风险、交易成本、实际控制变化及末端持仓。

已有仓位时，“退出后切 MR”的回放必须先模拟退出、部分成交/延迟、旧订单处理、重新准入，再让 MR 按自己的策略运行；不能把一个从空仓开始的 MR 影子收益贴到当前 TF 持仓上。

若不同专家在 H 末仍持仓，采用统一的期末清算价值及清算成本，或经过验证的同口径末端价值估计；不能只结算已平仓盈利而忽略残余风险。由于短 H 可能天然偏向短周期策略，需比较多个共同期限或做期限敏感性分析，不把各专家不同长度的单笔收益直接排序。

这些结果是特定执行模拟假设下的反事实，不是市场中已经实际发生的多条事实。数据不足以识别冲击、排队或延迟时应标注并压力测试；真实成交归因和影子结果始终分开。

### 11.4 训练标签可以使用未来结果，但在线状态不能

监督目标使用之后已经发生的收益是正常的训练方式；关键是未来结果不能进入当时状态，不能跨训练/测试边界，也不能让训练该样本所用专家提前看到这段未来。门控的“历史条件表现”特征同样只能用当时已经结束和可用的历史结果。

用完整历史回溯得到的最优策略切换只能作为指定约束下的诊断参照；不能把它的收益当成门控可实现收益。若参照只在有限候选策略/有限期限里最优，也不能称为整个市场的绝对收益上界。

### 11.5 专家更新会使门控关系失效

专家版本、动作语义、持仓保护规则或执行模型改变后，旧门控标签对应的被控对象已经改变。至少要重生成对应回放并重新校准；变化显著时需重训门控。不得只替换一个 `model.pth` 而继续沿用旧评分和阈值，除非经过明确兼容性验证。

## 12. 持仓高水位、奖励路径与 DP 教师一致性

### 12.1 用经济 Episode，而不是单一未实现盈亏

为避免部分平仓后“浮盈消失”造成假回吐，建议定义：

\[
G_t=\mathrm{RealizedPnL}_{\mathrm{episode},t}
+\mathrm{UnrealizedPnL}_{t}
-\mathrm{Fees}_{\mathrm{episode},t},
\qquad
H_t=\max\left(0,\max_{u\in\mathrm{episode},u\le t}G_u\right),
\]

\[
D_t^{\mathrm{cash}}=H_t-G_t,
\qquad
D_t^{\mathrm{risk}}=\frac{H_t-G_t}{\max(B_{\mathrm{entry}},\epsilon)}.
\]

`B_entry` 为明确定义的入场风险尺度或固定参考尺度，不能随切换重设。用真实成交价计算 PnL 时滑点已体现在价格差中，不再额外扣一次。另行归因滑点时必须采用与净资产一致的基准。

利润回吐比例可在峰值超过激活门槛后定义为 `(H_t-G_t)/max(H_t,h_min)`，但不是所有时刻都适合用接近零的峰值作分母。账户整体高水位应独立维护，不能因为一笔交易结束就清掉账户回撤历史。

仓位大小变化可能改变风险尺度，因此第一版优先使用固定且受限的风险分配，不把加仓作为抬高风险预算或重置利润保护的办法。若后续加入加仓，应单独规定 lot/Episode 归属和尺度变化规则。

### 12.2 对现有研究结论的必要限定

S3 指出高水位表征不足和退出阻尼过强，值得在方案 B 中验证。[S3，§3] 但其中“RL 对利润路径完全无感”“回吐过程没有负反馈”等表述不宜直接写成数学定理。若单步奖励为净资产增量，利润下降本来就产生负奖励；只有在特定无折扣加总等设定下，相同终值路径的总和才可能相同。

更准确的问题是：状态是否包含路径信息，目标是否表达回撤偏好，折扣与成本是否使必要退出不受重视，以及训练数据能否支持学习。加入高水位可以让前馈模型观察相关历史摘要，但不保证一定学出最优移动止盈；加入回撤惩罚也会改变优化偏好，需要检验。

### 12.3 扩展状态后，旧 DP 表未必仍然对应同一个问题

原有简化教师表主要按时间、当前仓位和目标动作递推。[S2，§3.3；S4，Algorithm 1] 引入持仓高水位、开仓成本、已实现 Episode 收益、冷静期和切换规则后，同一时点同一仓位可能因为历史不同而具有不同的未来允许动作和奖励。

因此，仅在原始三维 Q 表里多扣一个路径惩罚，不能自动得到正确教师。选择包括：扩充 DP 状态并明确离散化误差；使用能读取完整模拟状态的规则/滚动规划教师；或先保留净收益教师作有限辅助，再在完整状态环境训练和验证。第一版不强求求解无限扩展的精确 DP。

将原价格先经过因果 EMA，再对完整历史进行反向 DP，仍然使用了未来的滤波后价格。它可以改变教师偏好，但不能据此称教师已经没有未来信息。[S3，§6.4 中提出该方向；此处为本版的数学限定]

教师、专家训练、门控回放和在线推理应使用一致的环境状态转换、风险动作语义、持久化与成本合同；教师的额外可见信息必须单独声明。不能一边在线强制退出，一边让教师在同样状态无限继续持有并声称是同一问题。

### 12.4 规则保证的是控制行为，不是收益底线

硬掩码可以保证系统不主动发出被禁止的新仓意图；退出引擎可以保证按规则发出和管理退出请求。但跳空、流动性、拒单、断线和部分成交会影响结果，因此不能保证按照某个历史峰值的固定比例成交或锁定利润。S3 的固定回报和加仓翻倍收益推算不作为本版的验收目标。[S3，§5—7；本版边界]## 13. 验证、归因与工程验收

### 13.1 必须分开的对照实验

| 对照 | 要回答的问题 | 必须固定的条件 |
|---|---|---|
| 现有系统 vs 补充多尺度/持仓状态 | 增量来自信息改善吗 | 相同评估段、成本、风险和动作语义 |
| TF 单独、MR 单独、规则选择 | 专家本身有净收益能力和互补性吗 | 相同风险预算、数据可用性和成交假设 |
| 规则门控 vs 学习门控 | 学习是否优于可解释基线 | 冻结专家池、特征版本和执行规则 |
| 动态门控 vs 加滞回/所有权协议 | 稳定机制是否减少无效交易而不显著损害机会 | 不同时改变其他奖励和窗口 |
| 原保护规则 vs 高水位保护 | 回吐降低是否值得其机会损失与新增成本 | 不能只挑出现大回吐的合约调阈值 |
| 基础成本 vs 加重摩擦/延迟压力 | 优勢是否依赖乐观执行 | 压力情景提前定义并独立报告 |

所有可交易对照都保留基础硬风险，不用“完全无风控的账户”作为必须实际运行的基线。增加 PB、带仓接管或高层 RL 都需要新增单独消融，不与第一版的核心验收混在一起。

### 13.2 三层指标

**专家层：** 各市场条件下的净收益、尾部损失、平均/分位数持仓时间、反向新仓损益、回归失败损失、趋势退出质量、实际风险占用和预测/动作稳定性。专业化需要条件表现与行为证据，而非保证两个专家每次都做相反动作。

**门控层：** 相对固定/规则基线的净增量、选择覆盖率、拒绝交易比例、切换频率、切换引起的实际换手、切换后失效比例、继续/退出方案预测误差，以及误退出损失。不要为了让所有专家都有使用率而强制选择不可靠策略。

**系统层：** 扣费与滑点后的净资产、回撤、尾部风险、保证金/敞口占用、委托成功率、部分成交和拒单、订单延迟、残余敞口持续时间、人工干预、不同合约/年份表现和数据可用性。

采用按时间块或合约/交易 Episode 分组的稳定性与不确定性评估，不把密集相邻 Bar 当成大量独立证据。LOCO 与 Walk-Forward 结合使用；最终测试不得反复充当优化集。[S1，§九；本版设计]

### 13.3 真实账本归因原则

每个实际成交及其成本只计入一次真实账本。路由信号变化但没有实际交易，不产生佣金或已实现 PnL。旧仓退出的经济损益归旧 Episode；退出由高层切换、普通策略还是硬风险触发，作为控制原因另行统计。

影子专家和反事实方案的收益是模拟结果，不可与真实成交收益相加。多个合约共享资本时，组合收益应按一致的资金和时间口径计算，不能简单把各合约百分比相加。

`Gross PnL − Fees − Slippage = Net PnL` 只在毛收益采用未包含这些损耗的明确基准时成立。若 PnL 已使用实际成交价，滑点不能再次当作现金损失扣减。第 12 节的 RealizedPnL/UnrealizedPnL 定义为尚未扣单列费用的价格损益；若底层直接提供净损益，必须先转换为同一口径。

摩擦吞噬率在毛收益接近零或为负时可能失去常规解释意义，必须标注适用性，而不是用一个夸张比率概括全部性能。材料中的百分比和“全合约盈利”不应被默认当成可推广保证。

### 13.4 最低工程验收场景

| 场景 | 验收要求 |
|---|---|
| 特征批流一致性 | 相同历史与可用时间产生相同特征，允许误差范围提前定义 |
| 特征/标签未来信息 | 更改未来数据不得改变历史时点输入；边界标签不能越界 |
| 缩放与参考分布冻结 | 测试数据变化不得改变训练期拟合参数和选模决定 |
| 策略候选变化 | 无执行动作时实际仓位、成本、高水位与 owner 不变 |
| 强趋势下减仓 | 反向新增风险限制不能错误拦截降低当前风险的动作 |
| 反手与部分成交 | 旧仓未确认退出前不能启动新反向仓位 |
| 撤单中/迟到成交 | 旧开仓订单不能在完成交接后意外重建旧风险而无人负责 |
| 全部专家不可用 | 明确进入等待/防御，不在空集合上选择“最佳专家” |
| 普通驻留期间硬风险 | 风险能够抢占，且仍按真实成交更新残余敞口 |
| 模型/特征版本错配 | 拒绝新增风险，保留确定性风险与恢复流程 |
| 多合约并发开仓 | 全账户额度与挂单预占检查不被各合约独立判断绕开 |
| 决策重试与重复回报 | 不重复下单、不重复记账、不重复结束 Episode |
| 断线与重启 | 恢复订单、高水位和冷静期，完成外部对账后才开放新增风险 |
| 奖励/费用双计 | 实际账本、奖励塑形、滑点归因三者互相可核对 |
| DP/环境状态一致性 | 相同完整状态和动作得到一致的成本、风险转移和奖励 |
| 人工干预 | 必须带授权和原因，实际成交同样进入账本与审计 |

验收报告要展示失败案例，而不只展示收益曲线。无法从现有数据验证的执行或风控行为应标为未验证，不用模拟器的理想输出替代实际保证。

## 15. 实施顺序与本轮应收敛的决定

### 15.1 建议的阶段顺序

**第一阶段：先固定事实与合同。** 核对实际动作档位、槽位编码、合约单位、成本、仓位信息含义、已存在的风险和订单逻辑。落地 A05/A06/A13/A23/A24 的版本规则，补齐真实账本、Episode 与所有权状态机。此阶段不宣称新增模型带来收益。

**第二阶段：证明两个专家值得存在。** 固定数据与环境，分别训练 TF/MR，保留规则策略和现有系统对照，检查完整状态转移和条件表现。某族没有样本外优势可以暂时缺席，不能靠门控为一个无优势专家创造虚假价值。

**第三阶段：先跑可解释的方案 B。** 使用规则或简单条件表现路由，验证候选与 owner 分离、真实平仓后交接、拒绝交易和风险抢占是否正确。先解决执行逻辑再比较复杂模型。

**第四阶段：学习门控效用。** 冻结专家，用严格样本外反事实数据训练条件效用评分器，独立校准切换与拒绝规则，检验它是否超过规则门控。

**第五阶段：分别评估扩展。** 只有前述结果稳定，才研究独立 PB、族内更多专家、带仓接管或高层 RL。若引入可变持续时间的高层 RL，应按真实执行持续步数、期间回报和完整状态构造转移，不能直接把所有方案当成彼此独立的一步选择。

### 15.2 可以作为本版架构基线的决定

| 决定 | 基线 |
|---|---|
| 高层选择对象 | 可执行策略控制方案，而不是上涨/下跌槽位 |
| 初期策略池 | TF、MR、确定性防御；PB 后续独立验证 |
| 普通管理权 | 单合约单主动管理者，候选变化不自动变更 owner |
| 跨策略交接 | 真实平仓及旧订单确认后重新评估，第一版不带仓接管 |
| 防御语义 | 不新开仓、仅减仓、紧急退出分开 |
| 低层状态 | 多尺度市场信息 + 真实仓位/路径 + 订单/风险状态 |
| 训练顺序 | 先专家，后冻结，后门控；不直接端到端 |
| 可比评价 | 同起始状态、共同期限、同资金/风险、净成本口径 |
| 模型发布 | 专家、门控、特征、风险和执行规则原子版本绑定 |
| 最终评价 | 净增量、风险、摩擦、状态覆盖和工程可靠性，而非保证固定收益 |

### 15.3 实施前仍需真实资料解决的项目

本说明不能从现有文字材料确定：实际运行的 3/9 档动作配置；3×3/4×4 状态索引的最终含义；148 维与 55—70 维等不同特征口径的对应版本；`single_holding_max_drawdown` 在当前代码中的精确定义；真实可用历史和训练区间；盘口/成交数据是否足以验证执行假设；实际合约与账户费用/保证金配置；当前系统是否已经正确维护部分成交与未结订单。

这些项目应成为第一阶段的配置与接口审计输入，不妨碍先确定本版职责边界，但在解决前不能给出“可直接生产上线”或“预期达到某收益率”的结论。
