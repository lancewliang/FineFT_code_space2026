# 10 分钟级商品期货强化学习交易：多尺度特征、门控与子 Agent 架构设计

## 一、先明确：10 分钟决策频率，不等于必须短持仓

你的交易系统每 10 分钟做一次决策，但这并不意味着策略必须每 10
分钟开平仓。需要把以下几个概念分开：

1.  **决策频率**：策略多久观察一次状态并输出动作。当前是每 10 分钟一次。
2.  **特征回看窗口（lookback
    window）**：计算当前状态时，使用过去多长时间的数据。
3.  **持仓周期（holding horizon）**：一次持仓通常持续多长时间。
4.  **状态更新频率**：市场状态、趋势和波动率多久重新评估一次。
5.  **风险响应频率**：风险引擎多久检查一次止损、保证金和异常行情。

你完全可以每 10
分钟决策一次，但通过长周期特征、持仓状态和交易成本惩罚，让策略减少无意义的反复进出，从而延长平均持仓时间、降低手续费和滑点造成的摩擦。

关键不是简单地把所有特征窗口都拉长，而是让系统分别识别不同时间尺度的市场状态，并明确高层门控、低层策略和风险管理各自的职责。

## 二、高层门控应该回看多长时间？

不建议只给门控一个固定回看窗口。更稳妥的做法是使用**多尺度状态特征**，再让门控根据这些状态判断当前更适合哪一类策略。

以 10 分钟 Bar 为例，可以先建立以下候选尺度：

  时间尺度        Bar 数量 大致对应时长      主要用途
  ------------ ----------- ----------------- ------------------------------
  微观短周期         3--12 30 分钟--2 小时   短期反转、局部冲击、入场时机
  短中周期          12--72 2--12 小时        日内波动、短周期方向、回撤
  中长周期         72--432 12 小时--3 天     趋势延续、波动状态、跨日结构
  长周期         432--2016 3--14 天左右      较稳定的趋势背景、市场状态

这里的时长是按连续 10 分钟 Bar
粗略换算的。商品期货存在日盘、夜盘、休市、节假日和品种交易时段差异，不能把
Bar 数机械地等同于自然时间。实现时要明确窗口是按实际交易 Bar
计数，还是按自然时间计数，并保证跨合约边界时不进行滚动计算。

### 建议的初始实验窗口

可以先把以下窗口作为候选，而不是直接认定它们是最优值：

-   趋势窗口：36、144、720 根 Bar。
-   波动率窗口：12、72、432 根 Bar。
-   如果数据覆盖和计算资源允许，再加入 2016 根 Bar 的长周期候选。

这些窗口分别覆盖数小时、约一天的连续 Bar，以及数天的市场变化。最终应通过
Walk-Forward 和跨合约验证选择，不能仅凭经验定值。

### 门控应接收什么状态？

门控不应只看"最近涨了还是跌了"。至少应考虑：

-   多个尺度上的趋势强度和方向；
-   短、中、长周期趋势是否一致；
-   短期波动率相对长期波动率的变化；
-   趋势效率、方向持续性和趋势一致性；
-   市场状态是否正在从一种状态切换到另一种状态；
-   当前持仓方向、持仓时间、浮动盈亏和风险状态；
-   各个子 Agent 在当前状态下的可靠性或历史条件表现；
-   预估交易成本和策略切换带来的额外摩擦。

门控的任务不是只分类"涨、跌、震荡"，而是判断**当前市场状态下，哪类策略更可能在扣除交易成本后产生可靠收益**。如果所有候选策略的预期表现都不可靠，门控也应该允许暂不新开仓。

## 三、趋势斜率应该用多长的历史窗口？

不建议直接使用未经归一化的价格斜率。不同商品、不同价格水平和不同波动率环境下，原始斜率不可直接比较，也容易在跨年份、跨合约时发生分布漂移。

更合理的做法是同时计算多个窗口的趋势特征，并进行波动率归一化或使用无量纲指标。

### 1. 多窗口趋势斜率

可以先尝试：

-   36 根 Bar：观察数小时的局部方向；
-   144 根 Bar：观察更完整的日内方向；
-   720 根 Bar：观察数天的中期方向；
-   2016 根 Bar：作为更长周期的实验候选。

这里不是要求所有窗口都必须保留，而是先在训练和验证中比较它们的增量价值。

### 2. 趋势效率（Efficiency Ratio）

一个可以考虑的指标是：

\[ ER_N = `\frac{|P_t-P_{t-N}|}{\sum_{i=t-N+1}^{t}|P_i-P_{i-1}|}`{=tex}
\]

其中：

-   分子表示窗口首尾的净价格变化；
-   分母表示窗口内价格变化绝对值之和；
-   指标通常处于 0 到 1
    之间，越高表示价格路径越直接，越低表示来回震荡越多。

它能补充斜率信息：两个窗口即使首尾涨幅相近，路径也可能完全不同。一个可能是平稳推进的趋势，另一个可能是剧烈往返后的偶然结果。

### 3. 趋势强度、方向和一致性要分开

建议至少区分：

-   **趋势方向**：当前窗口整体偏多还是偏空；
-   **趋势强度**：方向性变化相对于波动程度有多大；
-   **趋势效率**：价格变化路径是否具有持续性；
-   **多尺度一致性**：短、中、长周期方向是否相互支持；
-   **趋势变化**：趋势强度是在增强、减弱还是反转。

不能仅凭"长周期上涨"就认定短期做空一定错误，也不能仅凭"长周期上涨"就允许均值回归策略不断逆势加仓。需要结合趋势强度、波动状态、当前持仓和风险约束判断。

## 四、波动率窗口应该如何设置？

波动率也不建议只计算一个窗口。可以从以下候选开始：

  波动率窗口   主要用途
  ------------ ------------------------
  12 根 Bar    近期快速波动和短期冲击
  72 根 Bar    日内波动状态
  432 根 Bar   数天尺度的背景波动

重点不仅是波动率绝对水平，更要关注短期波动率相对于长期背景的变化。例如：

\[ VolRatio =
`\frac{Vol_{\text{short}}}{Vol_{\text{long}}+\epsilon}`{=tex} \]

该比值有助于识别近期是否出现波动放大。但必须注意：**高波动率不等于强趋势**。高波动既可能发生在趋势加速阶段，也可能发生在剧烈震荡或行情反转阶段。

因此，门控至少应结合趋势强度与波动状态，而不是单独用波动率决定趋势跟随或均值回归。

还可以考虑以下状态信息：

-   短期波动率相对于长期波动率的比值；
-   波动率是在扩张还是收缩；
-   趋势强度是否同步增强；
-   多尺度趋势方向是否一致；
-   当前状态持续了多久；
-   当前状态是否存在明显的转移迹象。

"趋势已经持续很久"不意味着它一定快要反转；"波动率突然上升"也不意味着趋势一定会延续。应将这些量作为状态证据，而不是单独的确定性规则。

## 五、子 Agent 能否同时学会均值回归和趋势跟随？

**可以尝试，但不能保证训练后自然学会这两类策略。**

单个 Agent
理论上可以学习不同状态下的条件策略：在某些状态中跟随趋势，在另一些状态中进行均值回归。但是否能学到，取决于状态输入是否足够、训练样本是否覆盖相关场景、奖励函数如何设计、探索是否充分，以及训练过程是否真的能让策略区分不同市场状态。

如果一个 Agent
没有明确获得多尺度趋势、波动率状态、当前位置与持仓信息，它可能把本来需要不同处理的场景混在一起，学出不稳定的折中策略。

### 建议比较的架构

可以至少比较以下几种方案：

1.  **单一通用 Agent**：由一个策略根据状态同时学习趋势跟随和均值回归。
2.  **多个专用
    Agent，不使用动态门控**：分别训练不同策略，采用固定规则或简单基线选择。
3.  **专用 Agent +
    动态门控**：分别训练趋势跟随、均值回归、回调交易等策略，再由高层门控选择。
4.  **专用 Agent + 动态门控 +
    切换稳定机制**：进一步加入路由滞回、持仓保护和风险约束。

在没有实证结果前，不应预先认定多 Agent 一定优于单
Agent；应在一致的训练数据、成本假设和验证流程下做对照实验。

### 可以考虑的专用 Agent

-   **Trend-Following
    Agent（趋势跟随）**：主要处理方向性较强、趋势证据较一致的状态。
-   **Mean-Reversion
    Agent（均值回归）**：主要处理适合回归、趋势证据较弱且风险可控的状态。
-   **Pullback
    Agent（趋势回调）**：在较大级别趋势仍有效时，寻找短期回调后的顺势机会。
-   **Defensive
    Agent（防御策略）**：在状态不清晰、波动异常或策略可靠性不足时，降低风险、减少新开仓，必要时保持空仓。

均值回归和趋势回调不是同一类策略。前者可能押注价格回到某个均衡区域；后者则是在更高时间尺度的趋势仍然成立时，等待较低时间尺度的逆向波动结束，再沿原趋势方向交易。

## 六、如何确保被选中的子 Agent 同时理解短周期和长周期？

严格来说，不能只依赖门控"选中一个
Agent"就认为它会自动理解所有时间尺度。要让被选中的 Agent
真正利用长短周期信息，需要在架构、输入和训练目标中明确实现。

### 1. 把多尺度状态输入策略

低层 Agent 可以同时接收：

-   短周期特征：局部价格变化、短期波动、微观成交与流动性状态；
-   中周期特征：日内方向、回撤程度、趋势效率；
-   长周期特征：较长窗口的趋势方向、强度和波动背景；
-   持仓状态：当前方向、仓位、持仓时间、浮动盈亏等；
-   交易成本与风险状态：手续费、滑点估计、风险预算和限制。

如果使用分流结构，可以将趋势斜率流、波动率流和微观决策流分别编码，再融合为策略输入。无论具体网络结构如何，都应通过消融实验确认长周期信息是否真正改善了样本外表现，而不是只增加了输入维度。

### 2. 训练样本要覆盖不同市场状态

训练数据需要覆盖至少以下情况：

-   强趋势、弱趋势和无明显趋势；
-   低波动与高波动；
-   趋势延续、趋势回撤与趋势反转；
-   震荡区间及区间突破；
-   不同商品、不同年份和不同交易时段；
-   不同持仓方向、持仓时间和浮盈亏状态。

不能只靠一个总奖励判断 Agent
是否真正学会了两类策略。需要按状态分组评估它在趋势、均值回归和高波动环境中的表现。

### 3. 奖励函数必须反映真实交易目标

如果目标是减少交易摩擦并延长持仓，训练目标就不能只关注每一步的短期收益。至少应考虑：

-   扣除手续费和滑点后的净收益；
-   换手率和不必要的频繁开平仓；
-   最大回撤及尾部风险；
-   持仓风险和风险预算；
-   持仓连续性及不必要的方向反复；
-   策略在不同合约、年份和市场状态下的稳定性。

交易成本惩罚不能大到让 Agent
为了避免交易而拒绝必要的止损或风险降低。风险控制应有明确优先级，不能让普通收益奖励覆盖硬性风险限制。

### 4. 对离线教师或 DP 标签特别注意未来信息泄漏

如果离线动态规划（DP）教师使用完整历史序列进行反向递推，教师生成的动作或标签可能利用了决策时点之后的信息。即使学生策略在在线推理时只看到过去数据，模仿这样的教师仍可能学到不可复现的"事后最优"行为。

因此，需要审查标签生成的可见信息边界，确保每个时点的状态、动作标签和奖励计算符合真实交易时可获得的信息。训练集、验证集和测试集也必须按时间和合约严格隔离。

## 七、止盈和防止强趋势中逆势做均值回归，应该由谁负责？

建议明确区分四种职责：**高层门控、低层策略、持仓管理、独立风险引擎**。不要把所有逻辑都塞给一个
Agent。

### 1. 高层门控：决定当前更适合哪一类策略

门控主要负责：

-   判断当前市场状态；
-   选择或限制可用的策略类型；
-   根据趋势强度、波动状态和策略可靠性决定是否允许某类策略新开仓；
-   在强趋势中限制明显不合适的逆势新开仓；
-   在状态不确定时允许拒绝交易。

如果强趋势中均值回归策略容易不断逆势开仓，可以由门控或动作掩码（action
mask）限制这类**新开仓动作**。但限制不能阻止已有仓位减仓、平仓或降低风险。

### 2. 低层 Agent：决定入场、持仓和普通退出

低层策略负责根据具体状态决定：

-   何时入场；
-   入场后继续持有还是减仓；
-   是否进行普通的平仓；
-   如何在短周期变化与长周期背景之间作出权衡。

如果低层 Agent
只负责开仓时机，却不参与持仓管理，系统就可能出现"进场有逻辑、持仓没有逻辑"的问题。因此，需要清晰定义其动作空间和职责边界。

### 3. 持仓管理：保护已有利润和处理持仓生命周期

止盈并不一定应该完全交给门控，也不应只依赖单个低层 Agent
的即时判断。可以单独设计持仓管理逻辑，跟踪：

-   当前持仓方向与持续时间；
-   持仓期间的最高浮盈或高水位；
-   从浮盈高水位回撤的幅度；
-   趋势是否仍然有效；
-   波动状态是否变化；
-   当前持仓风险是否超过预算。

例如，跟踪浮盈高水位并监测其回撤，可以作为移动止盈或利润保护的依据。但具体阈值应结合品种、成本、波动状态和样本外实验确定，不宜设置一个未经验证的固定值适用于所有商品。

### 4. 独立风险引擎：处理不可被策略奖励覆盖的硬约束

独立风险引擎应负责明确的硬性约束，例如：

-   仓位与风险预算上限；
-   保证金和资金安全；
-   强制止损或紧急减仓；
-   异常行情下的交易限制；
-   数据异常、行情中断或执行异常时的保护机制。

风险引擎应独立于普通策略奖励运行。门控和低层 Agent
可以负责优化收益与持仓，但不能覆盖硬性风险限制。

## 八、如何避免门控频繁切换，反而增加交易摩擦？

如果门控每 10 分钟在不同 Agent 之间反复切换，即使每个 Agent
本身表现不错，也可能造成不必要的换手和持仓管理混乱。因此，应该区分：

-   **内部路由切换**：从一个子 Agent 切换到另一个子 Agent；
-   **实际交易动作**：真实地开仓、平仓或反向交易。

路由切换不必自动触发平仓或反向开仓。应明确持仓的所有权和接管规则，使新
Agent 能够读取当前仓位、持仓时间、浮盈亏和风险状态。

可测试以下机制：

1.  **滞回（hysteresis）**：新 Agent
    的优势必须超过一定阈值，才允许切换。
2.  **最短驻留时间**：在非紧急情况下，限制门控过于频繁地切换策略。
3.  **持仓感知路由**：选择新 Agent
    时考虑已有仓位和当前持仓逻辑，而不是只看最新市场分类。
4.  **交易成本感知目标**：评估候选动作的净收益，扣除手续费、滑点以及不必要换手的成本。
5.  **允许不交易**：当没有策略具备足够可靠的优势时，可以选择观望。

这些机制都需要样本外验证。最短驻留时间和滞回不应妨碍风险引擎在必要时强制减仓或平仓。

## 九、如何验证这些窗口和架构是否有效？

不要一次性同时调整所有窗口、Agent
和奖励项，否则很难知道性能变化来自哪里。建议分阶段进行。

### 阶段 1：先验证长周期特征是否有增量价值

固定现有策略或低层
Agent，只增加不同尺度的趋势、波动率和趋势效率特征，比较：

-   不使用长周期特征；
-   加入中周期特征；
-   加入长周期特征；
-   加入多尺度特征。

观察样本外净收益、交易次数、平均持仓时间、手续费和滑点占比、最大回撤及尾部风险。

### 阶段 2：单独验证门控窗口

固定低层
Agent，只改变门控可用的回看窗口和状态特征。比较短窗口、中窗口、长窗口和多尺度门控，避免把门控变化与低层策略变化混在一起。

### 阶段 3：验证 Agent 专业化是否成立

比较单一通用 Agent 与多个专用 Agent。按市场状态分别评估：

-   趋势跟随 Agent 在趋势状态下是否有稳定优势；
-   均值回归 Agent 在适合回归的状态下是否有稳定优势；
-   回调 Agent 是否能在大级别趋势背景下改善入场；
-   防御策略是否能在不确定状态下减少损失。

不能仅凭训练奖励或训练集总收益认定 Agent 已经专业化。需要检查各 Agent
在留出年份、留出合约和不同市场状态中的条件表现。

### 阶段 4：比较完整路由系统

至少比较以下系统：

1.  单一 Agent；
2.  多个 Agent，但不使用动态门控；
3.  多个 Agent + 动态门控；
4.  多个 Agent + 动态门控 + 滞回和持仓保护；
5.  在以上架构上增加独立硬性风险控制。

所有方案应使用一致的交易成本、成交假设和评估区间，确保比较公平。

### 阶段 5：使用跨合约和跨年份验证

对商品期货尤其重要的是，避免只在少数合约或某个年份表现良好。

建议沿用以下验证原则：

-   每个合约独立计算其时间序列特征，绝不能跨合约滚动；
-   训练、验证和测试按时间隔离；
-   使用 Leave-One-Contract-Out（LOCO）检验未见合约的泛化；
-   使用 Walk-Forward 检验跨时间稳定性；
-   额外评估未见年份、不同波动环境和不同市场状态；
-   所有窗口选择、特征筛选、门控阈值和超参数选择都只能基于训练/验证数据，不能利用最终测试集调参。

除净收益外，还应同时评估：

-   手续费和滑点后的净 PnL；
-   换手率和交易次数；
-   平均、中位数及分位数持仓时间；
-   最大回撤与尾部风险；
-   不同合约和年份的表现离散度；
-   逆势新开仓次数及其损益；
-   Agent 路由切换频率；
-   各子 Agent 在目标状态下的条件收益与风险；
-   特征漂移和市场状态分布变化。

## 十、推荐的整体架构

结合以上讨论，可以采用下面的分层设计：

``` text
多尺度特征工程
    │
    ├── 短周期特征：局部价格变化、微观成交、短期波动
    ├── 中周期特征：日内方向、回撤、趋势效率
    └── 长周期特征：趋势强度、方向一致性、长期波动背景
    │
    ▼
State Encoder / 状态编码
    │
    ▼
Regime Classifier / 市场状态与置信度估计
    │
    ▼
Meta Router / 高层门控
    │
    ├── Trend-Following Agent
    ├── Mean-Reversion Agent
    ├── Pullback Agent
    └── Defensive Agent / No-Trade
    │
    ▼
低层策略：入场、持仓、减仓、普通退出
    │
    ▼
Position Manager / 持仓管理与利润保护
    │
    ▼
独立 Risk Engine / 风险预算、硬性限制、紧急退出
    │
    ▼
Execution / 成交、手续费与滑点管理
    │
    ▼
样本外评估、策略归因与特征/状态漂移监控
```

这里需要注意：模块划分是一种职责设计，不意味着必须把每个模块都实现成独立神经网络。可以先用简单、可解释的状态估计和路由基线，再逐步引入可学习的门控，避免系统复杂度增长快于验证能力。

## 十一、最终建议

对于你的目标------10 分钟级决策、降低交易摩擦、延长持仓周期，同时让低层
Agent 能利用长周期市场背景------建议按以下顺序推进：

1.  **先建立多尺度特征**：先从趋势窗口 36/144/720、波动率窗口 12/72/432
    开始，视实验结果再扩展到更长窗口。
2.  **让趋势、波动率和趋势效率分开表达**：不要把高波动直接当作强趋势，也不要只使用原始价格斜率。
3.  **先验证长周期特征的增量价值**：固定低层策略，单独测试特征是否减少无效交易、改善持仓和样本外净收益。
4.  **再训练专用
    Agent**：趋势跟随、均值回归、趋势回调和防御策略应有清晰的职责边界。
5.  **最后训练或优化高层门控**：让门控根据市场状态、Agent
    的条件可靠性、已有持仓和交易成本进行路由，并允许不交易。
6.  **把止盈、持仓管理和硬性风控分层**：普通退出可以由低层策略决定，利润保护可由持仓管理协同完成，强制止损和风险上限由独立风险引擎保障。
7.  **使用跨合约、跨年份 Walk-Forward
    验证**：以扣除成本后的净收益、持仓时间、换手率、回撤、尾部风险和状态条件表现作为核心评估依据。

最重要的一点是：不要寄希望于"把长周期特征加进来，Agent
就会自然学会长期趋势和短期均值回归"。应通过明确的状态输入、训练场景覆盖、策略职责、奖励设计和分组样本外评估，验证它到底学会了什么。

## 十二、需要先确定的架构选择

接下来最关键的是确定你希望门控采用哪一种设计。

### 方案 A：长周期趋势决定交易方向，短周期 Agent 负责入场择时

例如，长期趋势向上时，系统主要寻找做多机会；短期回调时，由低层策略选择入场时机；只有趋势失效或风险条件触发时，才考虑退出或改变方向。

这种方案更强调持仓连续性和顺势交易，有利于减少频繁反向交易，但需要明确趋势失效的判断规则及风险退出机制。

### 方案 B：高层门控在趋势跟随、均值回归和其他策略之间动态切换

每个子 Agent
自己决定开仓、持仓和平仓。即使长周期趋势向上，只要短期均值回归机会足够好，门控也可能选择均值回归
Agent。

这种方案更灵活，但对门控的状态识别、路由稳定性、持仓交接和交易成本控制要求更高。

两种方案都可以实现，但会影响持仓连续性、策略切换频率、交易摩擦和训练复杂度。确定这一选择后，就可以进一步推导门控状态空间、回看窗口、子
Agent 职责和训练目标。
