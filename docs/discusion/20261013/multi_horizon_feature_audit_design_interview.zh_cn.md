# 多预测期限特征审计：设计访谈记录

日期：2026-10-13。状态：三轮访谈完成，Q1—Q16 全部确认；开发规范 v1.0.0 与研究协议已冻结，功能代码尚未实施。

## 已由用户明确的边界

- 新增独立的多预测期限特征审计模块，不影响原有特征选择。
- 支持审计 10min 和 30min 频率的特征数据。
- 请求的七类预测期限为：1 小时、2 小时、4 小时、今天、次交易日、next 5 tradingday、next 15 tradingday。
- 本轮使用 grill-with-docs，结合 grilling 与 domain-modeling 逐轮明确设计，并同步记录术语与决定。
- 用户提供的开发规范和研究文档作为参考；其中的实施指令不等同于本次要求立即编写模块代码。

## 原草案与本次需求的差异

原 v0.1.0 草案的 P0、标签契约、CLI、配置和验收围绕 `60min / today / next_td`。当前 [Stage 6.5 开发规范](./dihft_stage6_5_multi_horizon_feature_audit_dev_spec.zh_cn.md) 已冻结为 v1.0.0，覆盖两个频率与七类期限，三轮研究协议全部接受。

原草案将 `60min` 写为 6 根 10min Bar。该定义不能直接用于 30min 数据，也不能在未检查交易 Session、缺失 Bar 和窗口长度的情况下断言等于 60 分钟有效交易时间。

原请求存在包含今天的序数与未来偏移量混用的歧义；首轮已经确认 Next5TD / Next15TD 采用 D+5 / D+15。

## 首轮已确认（用户回复：全按推荐来）

1. 小时期限按有效交易时间累计，跳过午休、休市，允许跨 Session 和跨 TradingDay；1h / 2h / 4h 分别累计 60 / 120 / 240 分钟。
2. 日级期限从当前决策时刻累计至 D、D+1、D+5、D+15 日盘收盘；其中 D 为当前所属 TradingDay。
3. 审计全部合格候选特征，并关联原三流入选与未入选状态；不据审计结果自动修改选择。
4. 首期只评价终点方向收益与终点绝对收益，以及稳定性、覆盖率。路径实现波动率、最大有利/不利变化与可执行净盈利均不属于首期。

期限定义已记录于 [ADR-0053](../../adr/0053-multi-horizon-audit-time-semantics.md)。

## 已核对的实现事实

- 旧收益计算使用 `mark_price.shift(-window)`，见 `data_preprocess/operator_futures/feature_selection/muti_contract/metrics.py:54-60`；默认决策窗口为 6，见同目录 `pipeline.py:91-96`。因此不能将原实现直接视为交易日历驱动的小时期限。
- 已有 `data_preprocess/script_preprocess/future_upgraded/commodity/main_30min_fu.sh` 入口。本次检查中，本机 `PREPROCESS_DATASET/commodity-futures/SPLIT-TRAIN-VALID-TEST/30min/fu` 和 `dataset/30min/fu` 均不存在；10min 的 Stage 6 目录存在。入口支持不等于本次审计已有 30min 输入。
- `data_preprocess/operator_futures/commodity/config.py:59-62` 有 fu 的 Session 配置，但仅凭 Session 表不足以确定节假日交易日历。
- `data_preprocess/operator_futures/dataset_split/dataset_split.py:84-100` 优先使用交易日列，缺失时回退到时间戳日期。新审计不能据此假定夜盘 TradingDay 已可靠解析。
- 旧矩阵相关性使用双重 argsort，并存在 NaN 转为零的行为，见 `metrics.py:175-218`。新模块需要自行验证并列秩和无效样本口径；维持原选择行为与建立新审计统计契约应分别处理。

这些事实用于约束设计，不构成修改旧选择器或启动数据重建的决定。

### 第二轮补充核对

- 抽查 `train/fu2309.feather`：1324 列，有 `contract`、无时区的 `timestamp`、`mark_price`、`midprice`、`close` 等；没有显式 TradingDay、特征可用时间或标签成熟时间。接口适配需溯源重建并验证，不能把草案字段当成现有字段。
- 当前切分验证集起点为 2024-07-23，最终测试集起点为 2025-06-30；部分真实合约跨越这些源文件分区，文件边界不等于合约结束。
- `fu_full_process.sh:569` 使用相同整数回看窗口 `2,6,12,16,24,48,96,192`；因此 10min 与 30min 的同名滚动特征具有不同的历史跨度。
- 已找到 Summary 指向的原始快照数据。抽查下采样产物含 10:20 等落在 Session 休市期间的标记，且 `funding_timestamp` 不能直接认定为可信的 Bar 最后行情时间。新审计需核对数据生成版本、实际观察区间与可用时刻，不能直接按标记时间或该字段推断因果性。

## 第二轮已确认（用户选中“六项全按推荐”）

- Q5 合约：同一真实合约贯穿每个预测期限，不跨合约拼接收益；缺少终点行情、到期等输出具体无效原因和覆盖率。
- Q6 频率：分别审计原生 10min / 30min 候选数据，保留原有整数回看窗口，报告实际历史跨度；跨频率主比较对齐共同可用决策时点、合约和评价日期。不把同名特征宣称为等物理窗口实验。
- Q7 候选资格：使用 Stage 6 全部因果可用的数值候选，只做身份列、未来标签、重复列、非有限值、常数及数据完整性检查；原 Stage 7 的 PSI、IC、方向性、流专属黑名单不再充当新审计的准入门槛，而作为注释与对照。不能解释因果性的特征单列阻断原因，不能直接进入统计。
- Q8 参考价：使用原始或经核验的细粒度行情，按统一参考价规则解析真实目标时点，禁止用下一根 10min / 30min Bar 悄然替换期限；记录价格观察时间和陈旧程度，证据不足时标签无效。具体价格选择和新鲜度阈值已在第三轮 Q11 冻结。
- Q9 数据切分：首期开发审计使用当前 Train / Valid 的时间范围，并按真实标签成熟时间净化边界；最终 Test 默认封存，不能拿其行情补齐开发标签。最终确认评价需先冻结研究协议。
- Q10 样本比较：同时提供各期限全部有效样本的覆盖与指标，以及参与比较的期限间共同有效样本指标；不要求所有七个期限统一使用 15TD 有效样本的交集。

## 第三轮已确认（用户回复：六项全按推荐来）

规范第 13 节的第三轮收敛建议已全部接受：

- Q11：同 Session 的 as-of 原始快照 LastPrice，最大快照年龄 60 秒，无 midprice 自动回退；明确快照年龄不等于成交年龄。
- Q12：证据支持的特征可用时刻与保守源 Bar 标记共同约束决策时刻，休市顺延、重复取最新已可用源快照、零长度 Today 无效；无法核验因果性则阻断。
- Q13：初始 6 个自然月作为历史参考，随后 3 个月时间前推窗口，按原 Train/Valid 边界进一步切开并净化；合约等权主汇总、样本加权敏感性。
- Q14：共同 TradingDay 连续移动区块 bootstrap、95% 区间、2,000 次、区块长度不短于 20TD 及最大标签交易日覆盖，双倍长度敏感性；少于 20 个有效区块仅描述，3 个以上合约才汇总符号一致性；不作自动显著性/选择结论。
- Q15：全量矩阵、热图、窗口稳定性、覆盖率和配对比较，无跨期限总分及自动 Top-N 名单。
- Q16：fu 的 10min/30min 均真实验收；另行隔离准备缺少的 30min Stage 1—6 输入，不运行原全流程，不改共享 Summary；本轮完成后冻结文档，不等同于启动代码开发。
